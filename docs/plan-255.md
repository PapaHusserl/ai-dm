# 255. Чистка истёкших эффектов в сейве (BACKLOG 255)

## Суть

Истёкшие эффекты и состояния со сроком `seconds` не удаляются из существ и копятся в сейве навсегда; каждый
потребитель фильтрует сам. Нужна чистка. План — папа-кабан (разделы «Файлы» и ниже).

**Правило:** было — истёкший `seconds` остаётся в `creature.active_effects` и `creature.conditions`; эффекты прячет
только `live_effects(creature, now_s)` (rules/creatures.py:25-31), у `conditions` фильтра по `now_s` нет вовсе
(grep `conditions` × `now_s` по src — 0 совпадений) → станет — после каждого сдвига часов запись с
`expires.kind == "seconds" and expires.value <= now_s` удаляется из обоих списков у героев бандла и NPC мира;
исключение — `kind == "max_hp"`: его снимает только `expire_max_hp` (rules/healing.py:52-63).

**Правило 2 (решение 11):** было — истёкший призванный (`minion.until_s is not None and minion.until_s <= now_s`,
`expired`, combat/minions.py:15-16) уходит из `hero.minions` только в `after_combat` (combat/minions.py:83-98), вне
боя лежит до следующего боя → станет — после каждого сдвига часов он удаляется из `hero.minions` у героев бандла,
если `bundle.session.active_combat is None`; в активном бою список не трогается (индекс в списке — часть ref
участника, `minion_ref`, combat/minions.py:11), там по-прежнему работает `after_combat`.

**Поведение:** меняется в одном месте — состояния (`conditions`) со сроком `seconds` начинают кончаться по часам
мира (сейчас висят вечно) — решение 10. Эффекты и призванные: на экране, в промпте и в бою без изменений
(потребители уже фильтруют: `live_effects`; `texts` и `participants`, combat/minions.py:56, :19).
**Вне репо:** нет.

Без решения 11: кода меньше на ≈ 5 строк, тестов на ≈ 30 (оценка, не измерено); теряем — истёкшие призванные
остаются в hero.json до следующего боя.
