# Партия «Переговоры в бою» (parley) — план

Папа-кабан, 2026-10-06, на утверждение. Идея пользователя 2026-10-06: поговорить с противниками во время боя —
переманить на свою сторону, запугать, убедить сдаться/отступить. Код не меняется до аппрува.

**Задача:** социальное действие героя в бою (Убеждение/Запугивание/Обман) с исходом, который решает движок;
рассказчик классифицирует фразу и озвучивает реплики врага, но исход не выбирает.

## 0. Что уже есть (опора)
- `combat/actions/improvise.py` — проверка навыка (`rules/checks.skill_check`, СЛ из таблицы `dc` по категории)
  ради фиксированного эффекта из `EFFECTS`; LLM задаёт skill/category/effect/target через `PlayerAction.improvise`
  (`protocol/requests.py::ImproviseSpec`). Категорию СЛ сейчас выбирает LLM — для переговоров это НЕ годится
  (исход должен решать движок), см. п.2.
- `state/combat.py::Participant`: `side: Literal["heroes","enemies"]`, `status: active|down|dead|fled`,
  `controller: engine|auto_hero|external`, `monster_id`, `creature` (безымянные), `group_id`; `Group.intent`
  (kill/capture/rob/drive_off/spare).
- `standard.py::flee` → `status="fled"`; `end.py::set_outcome` считает стороны по `side` и `is_capable`.
- Именованные NPC: `state/world.py::Npc.attitude` (-100..100), `follows` (напарник), `combat` dict;
  `protocol/handlers/world.py::change_attitude` с лимитами `[attitude] step/per_scene`.
- `content/models/monsters.py::Monster`: `abilities` (есть INT/WIS/CHA), `creature_type`, `cr`.
- ИИ: `combat/controllers.py::EngineTactics` (враги по `side`), `AutoHeroController`; `npc_action` для ключевых NPC.

## 1. Механика (SRD 5.2: Social Interaction, Attitude; Influence action)
SRD 5.2 даёт действие **Influence**: проверка Убеждения/Запугивания/Обмана (и др.) против СЛ, зависящей от
отношения: Дружелюбный — легко/без проверки, Безразличный — СЛ 15 (по умолчанию), Враждебный — проверка с
помехой либо невозможно (решение мастера); СЛ по умолчанию 15 или Инт существа, если она выше; «неохотная» просьба
— провал без бонусов. Берём это ядро и добавляем боевые модификаторы.

**Навыки → допустимые исходы:**
| Навык | Исходы | Комментарий |
|---|---|---|
| Запугивание (intimidation) | сдаётся / бежит | страх; не переманивает |
| Убеждение (persuasion) | сдаётся / бежит(отступает) / переходит на сторону | честное предложение |
| Обман (deception) | бежит / колеблется (теряет ход) / ссорится с союзником | ложь («подкрепление идёт», «он вас предаст») |
Игрок называет цель-исход («сдавайся», «уходите», «присоединяйся»); движок проверяет, допустим ли исход для навыка.

**СЛ (всё в конфиге `[parley]`, числа — предложение):**
- База 15 (SRD); если Инт цели > 15 — Инт цели.
- Отношение: именованный NPC — из `npc.attitude` (≥ +30 дружелюбный: −5; −29..+29 безразличный: 0; ≤ −30
  враждебный: помеха на проверку). Безымянные монстры — враждебные по умолчанию (помеха).
- HP цели: ≤ 50% → −2; ≤ 25% → −5.
- Потери стороны цели: ≥ половины группы `down/dead/fled` → −3; лидер группы выведен из строя → ещё −3.
- Перевес героев (боеспособных героев ≥ 2× врагов) → −2 только для Запугивания.
- «Переход на сторону» — +5 к СЛ (тяжелее всего); «колеблется» — −2.
- Босс/ключевой (`npc.key` или флаг монстра `boss`, см. В5) → +5 и исход «переходит» запрещён.
- Повторная попытка по той же цели — +5 за каждую (если разрешаем, В3).
Помеха/преимущество — через существующий механизм `skill_check` (проверить, принимает ли mode; иначе добавить
параметр — локально).

**Ограничения (отказ без траты действия, `Rejected`):**
- Цель неразумна: Инт ≤ 3 (звери, слизи) или `creature_type` в списке `[parley].immune_types` (нежить безмозглая,
  конструкт, слизь, растение). Разумная нежить (вампир, лич) — можно, через Инт > 3 и не в immune (см. В4).
- Нет общего языка — по рекомендации НЕ моделируем (в контенте языков нет), Запугивание работает жестами всегда.
- Цель не `active` (down/dead/fled) или уже сдалась/перешла.
- Цель не слышит: другой зоне не соседней — отказ (зоны есть, `zones.py`); в соседней — можно (крик).
- Одна попытка на цель за бой (рек.) — флаг в `ActiveEffect(id="parley_tried", kind="flag")` на существе цели.
- Герой без действия (`turn.action`) — отказ.

**Стоимость:** Действие (SRD Influence — Action). Рек.: действие; Запугивание как бонусное — нет (простота).

## 2. Исходы (решает движок, по результату проверки)
- **Успех на 10+ сверх СЛ / нат.20** — «сильный успех»: выбранный исход + распространение: при «сдаётся/бежит»
  проверка морали остальных в группе (простая: каждый с HP ≤ 50% тоже сдаётся/бежит) — см. В6, по умолч. выкл.
- **Успех** — выбранный исход для цели.
- **Провал** — ничего; при провале на 5+ у «переходит» — цель «оскорблена»: следующую атаку по герою с
  преимуществом (ActiveEffect modifier с consume, как `apply_advantage`), именованному NPC `attitude` −10 через
  `change_attitude`-логику.
Реализация исходов:
- `surrender` (сдаётся): новый `status="surrendered"` (расширение Literal) — не боеспособен (`is_capable` = False,
  т.к. проверка `status=="active"`), пропускает ход (engine.py:418 — добавить в список), не цель для ИИ врагов.
  Атака по сдавшемуся — разрешена игроку (его выбор), но см. риск R5.
- `flee` (бежит/отступает): переиспользовать `standard.flee` логику → `status="fled"` (провоцированные атаки не
  делаем — сдался добровольно; рек.).
- `defect` (переходит): `side="heroes"`, `controller="engine"` (ИИ союзника = `EngineTactics`, т.к. `enemies()` уже
  считает врагов по side — инвертируется само), `group_id` → группа героев, `intent` сбросить. Лог «X переходит на
  вашу сторону».
- `waver` (колеблется): `ActiveEffect(id="wavering", kind="flag", expires end_of_turn цели)` — пропуск следующего хода.
- `quarrel` (ссорится, Обман): цель на своём следующем ходу атакует ближайшего союзника по группе (эффект
  `kind="turncoat_once"`; `EngineTactics.enemies()` учитывает его один ход). Сложно — см. В2 (рек. отложить).

`end.py::set_outcome`: `enemies_fit` уже исключает surrendered/fled; перебежчик в heroes → победа, когда враги
кончились. Новый outcome не нужен.

## 3. Выбор действия: меню и/или фраза
Рек. (В1): **оба, через единый путь**.
- Меню (`available.py`): на каждую разумную цель в своей/соседней зоне одна опция `parley:<target>` kind "parley"
  с подменю навык×исход (TUI раскладка «Действия»). Чтобы не раздувать меню (R1 из EXTRAS) — одна строка
  «Переговоры: <имя>», второй шаг выбора.
- Фраза: `PlayerAction` получает поле `parley: ParleySpec{skill, outcome, target}` (по образцу `ImproviseSpec`,
  NEUTRAL, валидатор «всё или ничего»). Категорию СЛ LLM НЕ передаёт — СЛ считает движок. Рассказчик
  классифицирует «сдавайтесь, или…» → intimidation/surrender. В промпт инструментов (game/turn.py) — строки:
  «уговоры/угрозы/ложь врагу в бою — parley, не improvise; исход и СЛ задаёт движок».
- Новый модуль `combat/actions/parley.py`: `check_request` (по образцу improvise), `parley_dc(engine, ref, target,
  skill, outcome)` → (dc, mode, parts для лога), `parley(...)`, `APPLY = {surrender, flee, defect, waver}`.
  Регистрация в `engine.py` таблице действий (рядом с `"flee": standard.flee`).

## 4. Роль рассказчика
- Классифицирует фразу → ParleySpec (как improvise).
- После решения движка в `combat_narrate` получает факт (`parley: target, skill, outcome, success, dc`) и пишет
  реплику врага, соответствующую исходу. Не может сменить исход: в combat_narrate нет инструмента, меняющего
  side/status (schema.py:19 — список не расширять).
- Ключевые NPC (`npc_action`) — по рекомендации проверка такая же; рассказчик лишь озвучивает.

## 5. ИИ перебежчика
- `controller="engine"` + `side="heroes"` → `EngineTactics` бьёт бывших союзников. Нелетальные удары не нужны.
- Не берёт под контроль игрок (рек., В7); в будущем — `auto_hero` по аналогии с напарником.
- Не лечит/стабилизирует героев (EngineTactics этого не умеет — норм).

## 6. После боя
- Безымянный сдавшийся/перебежчик: в лог итога «пленный/ушёл с миром»; в мир НЕ сохраняется (рек., В8) —
  исчезает после боя, рассказчик может упомянуть. Награда/опыт — как за побеждённого (XP по CR; сверить
  `end.py::conclude`), рек.: да, SRD даёт XP за «преодоление».
- Именованный NPC: сдался → `status` остаётся alive, `attitude` +10 (через лимиты attitude), рассказчик решает
  дальнейшее обычными world-инструментами. Перешёл → `attitude` +20 (cap per_scene), предложение `follows` —
  нет автоматически (рек.), рассказчик/игрок через существующие механизмы напарника.
- Сейв посреди боя: новый status и эффекты сериализуются как есть.

## Миграции сейва
Не нужны: `Participant.status` — расширение Literal (`"surrendered"`) читает старые сейвы; ActiveEffect kind/params —
свободные str; `PlayerAction.parley` — протокол, не сейв. CURRENT_SCHEMA_VERSION=5 не меняется. Живые saves/ не
трогать. Тест: фикстура v5 (в т.ч. с активным боем) грузится; новый сейв с surrendered грузится обратно.

## Тесты (TDD, писать первыми)
СЛ/ограничения:
- база 15; Инт 18 → 18; HP 40% → −2; HP 20% → −5; половина группы выбыла → −3; лидер выбыл → ещё −3.
- безымянный монстр → помеха; NPC attitude +40 → −5 без помехи; −50 → помеха.
- defect +5; key/boss → defect отказ, прочие +5.
- Инт 3 → отказ `not_sentient`, действие не потрачено; immune creature_type → отказ; Инт 10 нежить не в immune → ок.
- цель down/fled/surrendered → отказ; дальняя зона → отказ, соседняя → ок.
- вторая попытка на ту же цель → отказ (или +5 по В3); нет действия → отказ.
- intimidation+defect → отказ `outcome_not_allowed`.
Исходы:
- успех surrender → status surrendered, ход пропускается, `is_capable` False, ИИ врагов его не цель.
- успех flee → fled; все враги fled/surrendered → outcome victory.
- успех defect → side heroes, атакует бывших союзников (ScriptedController/RNG-фиксация); последний враг перешёл → victory.
- waver → пропуск ровно одного хода.
- провал на 5+ при defect → преимущество следующей атаки цели по герою, consume; NPC attitude −10 с лимитом.
- действие тратится при любом броске; лог содержит навык, СЛ, части модификаторов.
Протокол/рассказчик:
- PlayerAction с parley без target → ValidationError; parley и improvise вместе → ValidationError (рек.).
- combat_narrate не может изменить side/status (регрессия schema.py).
- improvise работает как раньше (регрессия).
После боя: NPC сдался → attitude +10 в пределах per_scene; безымянный перебежчик не попадает в world.npcs; XP начислен.
Сейв: v5 без изменений грузится; roundtrip с surrendered.
Мутационное тестирование — по HANDOFF (без недостижимых фолбэков).

## Риски
- R1 Переговоры сильнее урона: Убеждение 15 против одиночного врага заканчивает бой одним действием. Ограничители:
  помеха для враждебных, +5 defect, раз на цель. Проверить на живом прогоне, числа в конфиге.
- R2 LLM путает improvise/parley или подсовывает исход, которого игрок не говорил — валидация навык×исход, лог.
- R3 `skill_check` может не поддерживать помеху — проверить, при необходимости параметр mode.
- R4 Список мест, где status "active"/"fled" проверяется вручную (engine.py:418, end.py, available.py, downed.py,
  controllers.py, stealth.py) — surrendered надо пройти grep'ом по всем; тест на каждое место.
- R5 Атака по сдавшемуся — морально/механически: рек. разрешить, но сдавшийся враг при уроне снова «active»? Рек.: нет,
  остаётся surrendered (просто бьют лежачего) — упрощение.
- R6 Перебежчик-именованный NPC при сейве в бою: его `creature` в world.npcs — side хранится в Participant, ок.
- R7 Ключевые NPC с `npc_action`: их ход выбирает LLM из вариантов движка — после defect варианты считаются от новой
  стороны (проверить available для side heroes у не-героя).
