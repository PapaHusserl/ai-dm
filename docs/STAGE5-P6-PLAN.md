# Этап 5, P6 «ASCII-рисунки» — план (папа-кабан, 2026-10-06, на утверждение)

Основание: docs/decisions/stage5-live-1.md п. 9 (пересмотр Q2/В7). Прежняя спецификация: stage2-live-1.md V3/V5.
Решение пользователя: готовые рисунки в контенте (без LLM) — локации (вход в место), монстры (начало боя),
заставка и события (титул, победа, смерть, новый уровень).

**Задача:** показывать готовые ASCII-рисунки из каталога контента в панели `#picture` TUI по событиям игры.

## 1. Где хранить — отдельный каталог рисунков, НЕ поле `ascii` в Location
Почему не поле: `state/world.py::Location` (`extra="forbid"`) живёт в сейве (`slots/*/world/world.json`) — поле потребует
миграцию m0006 и правку живых сейвов; `Monster` — контент SRD (тоже `extra="forbid"`). Каталог по ссылкам не трогает
сейвы вообще.
- Файлы: `src/ai_dm/art/data/<id>.txt` (один рисунок = один файл, читается как есть, без YAML-экранирования).
- Индекс: `src/ai_dm/art/data/index.yaml` — модель `ArtIndex` (pydantic, `extra="forbid"`):
  - `events: {title, victory, death, level_up}` → id рисунка;
  - `locations: {<location_id>: art_id}` — точные ссылки (для Вейла и «Пьяного дракона»);
  - `location_tags: {<tag>: art_id}` — фолбэк по тегу локации (таверна, болото, руины, храм, деревня, горы, город,
    магазин, гробница, равнина…), порядок тегов локации = приоритет;
  - `monsters: {<monster_id>: art_id}`; `creature_types: {humanoid, beast, undead, …: art_id}` — фолбэк по `Monster.creature_type`.
- Модуль `src/ai_dm/art/__init__.py`: `load_art()` (кэш), `art_for_location(loc)`, `art_for_monster(mon)`, `art_for_event(name)`
  → `str | None`. Цепочка: точный id → тег/тип → None (рисунка нет — панель скрыта, как сейчас).
- Паки/миры пользователя могут позже добавить свой `art/` (оверлей поверх встроенного) — **не в P6**, только место в API.

## 2. Когда и где показывать (только TUI)
- Панель `#picture` в правой колонке (уже есть, скрыта). Рисунок заменяется по событию и висит до следующего;
  в ленту рисунки не печатаем (лента — рассказ, п. 7–8 live-1), кроме заставки.
- События: вход в новую локацию (смена `location_id` после хода, как в V3) → локация; старт боя → первый живой враг;
  победа / смерть / новый уровень → рисунок события (поверх, до следующего хода); титул — заставка при старте в ленте
  (до выбора героя) и в `#picture`.
- Узкий режим (< WIDE=120, `#side` скрыт/выдвижной): `#picture` в выдвижной колонке, ничего в ленту не дублируем.
  Ширина: рисунок ≤ 36 колонок × ≤ 14 строк (V3) — влезает в `#side` (58) с рамкой; заставка ≤ 76 × 16 (лента).
- Точка вызова: там же, где сейчас обновляются «Бой»/«Получено» после хода (`ui/tui/app.py` + `widgets.py`), выбор рисунка —
  чистая функция `pick_picture(prev_state, state, events)` в `ui/screen.py` или `art/`, чтобы тестировалась без Textual.

## 3. Простой режим
Рекомендация: не показывать (V1: «< 120 → без рисунков», решение В1 «только TUI», п. 7–8 — «простой режим без изменений»).
Исключение на выбор пользователя — только заставка-титул при старте (В-2).

## 4. Минимальный набор (≈ 20 рисунков)
- События (4): титул «ИИ-мастер» (≤ 76×16), победа, смерть (надгробие), новый уровень.
- Монстры (3 точно + 3 по типу): goblin_warrior, goblin_boss (Гракх), guard; фолбэк humanoid, beast, undead.
- Локации Вейла (3, из V3): таверна, подвал, деревня у реки — точными ссылками.
- Теги локаций (≈ 10, покрывают «Пьяного дракона» без ссылок по id): таверна, город, деревня, болото, руины, храм/святилище,
  магазин, горы, гробница/курган, равнина. Локации без тега/без совпадения — без рисунка.

## 5. Кто и как рисует
- Рисует агент (кабан) вручную по списку п. 4, тон «старой книжной гравюры», только ASCII 0x20–0x7E (+ по решению
  пользователя псевдографика ширины 1: `─│┌┐└┘░▒▓`). Без копирования узнаваемых работ (ascii-art архивы, чужие подписи),
  без подписей авторов. Лицензия — своя, как у остального контента проекта; источник фиксируется `source: custom`
  в index.yaml. Пользователь смотрит рисунки на живом прогоне и может забраковать/заменить файл.

## 6. Миграция мира и сейвов
Не нужна: схема `Location`/`Monster` и `CURRENT_SCHEMA_VERSION=5` не меняются, сейвы (`saves/`) не трогаем. Рисунки
«Пьяного дракона» подхватываются по тегам. Если пользователь захочет точные ссылки для своих локаций — это правка
`art/data/index.yaml` (код), не сейва. `import_dragon.py`/`dragon_drafts.yaml` не меняются.

## 7. Тесты и сторожа (TDD, kaban-doeba)
- Сторож каталога (тест по всем файлам): каждая строка ≤ лимита ширины, строк ≤ лимита, только допустимые символы,
  нет табов/хвостовых пробелов, `rich`-разметка экранирована (нет `[`… или рисунок выводится как `Text`, не markup);
  `wcwidth`/`cell_len` каждого символа = 1.
- Индекс: все art_id из index.yaml существуют; нет файлов-сирот; все id монстров в `monsters` есть в SRD; все id локаций
  есть в паке Вейла; все 4 события заданы.
- Выбор: точный id локации → его рисунок; нет id, есть тег → по тегу (первый совпавший тег по порядку); нет ничего → None;
  монстр без точного → по creature_type; неизвестный тип → None.
- `pick_picture`: первый ход → локация; смена локации → новая; та же локация → без замены; старт боя → первый живой враг;
  победа/смерть/уровень → событие; смерть приоритетнее победы/уровня.
- TUI (pilot): `#picture` скрыт без рисунка, виден с рисунком; при 100 и 140 колонках рисунок не обрезан и строки не переносятся;
  заставка в ленте при старте.
- Простой режим: вывод не изменился (существующие снимки зелёные; при В-2 «да» — только заставка).
- Мутанты — по изменённым функциям (правила экономии HANDOFF).

## 8. Шаги
1. `art/` модуль + `ArtIndex` + загрузчик + сторожа каталога (на 2–3 пробных рисунках). Тесты выбора.
2. `pick_picture` и подключение к `#picture` в `ui/tui/app.py`/`widgets.py`, заставка в ленту; CSS высоты `#picture`
   (`app.tcss`) — не отбирать место у «Бой»/«Ход боя» (live-1 п. 2): рисунок сворачиваемый/ограниченной высоты.
3. Контент: все рисунки по п. 4 + index.yaml. Живой просмотр пользователем (скриншоты 120/160).
4. Документы: ARCHITECTURE (раздел «Рисунки»), README (как добавить рисунок), BACKLOG 5 закрыть; review.md партии.
Затронутые файлы: новый `src/ai_dm/art/` (+ `data/`), `src/ai_dm/ui/tui/app.py`, `widgets.py`, `strings.py`, `app.tcss`,
возможно `ui/screen.py` (pick_picture), `pyproject` package-data для `*.txt`/`*.yaml`, тесты `tests/unit/art/`, `tests/unit/ui/tui/`.

## Риски
- Высота правой колонки: рисунок 14 строк съест «Бой»/«Броски» (жалоба live-1 п. 2) → `#picture` ограничить по высоте, в бою
  можно сворачивать после первого хода (см. В-4).
- Rich-разметка: `[`/`]` в рисунках ломают вывод — выводить как `Text`.
- Package-data: .txt не попадут в колесо без настройки — проверить `make linux-check`.
- Качество рисунков агентом субъективно — нужен просмотр пользователем.

## Вопросы пользователю (с рекомендацией)
- В-1. Хранение: отдельный каталог `art/` со ссылками и фолбэком по тегу/типу (без миграции сейвов) vs поле `ascii` в
  Location/Monster (миграция m0006 + правка сейвов). **Рекомендую каталог.**
- В-2. Простой режим: без рисунков / только заставка / всё. **Рекомендую без рисунков** (или только заставка).
- В-3. Символы: чистый ASCII или + псевдографика (`─│┌┐░▒▓`). **Рекомендую ASCII + блоки `░▒▓`** (ширина 1, гравюрная штриховка).
- В-4. В бою рисунок монстра: держать весь бой / только первый ход, затем свернуть. **Рекомендую первый ход, затем свернуть**
  (место «Бою»).
- В-5. Объём: минимум ≈ 20 (п. 4) или точные рисунки для всех ~31 локации «Пьяного дракона». **Рекомендую минимум**, точные — в BACKLOG.

## Ответы проектировщика (2026-10-06)
В-1 — отдельный каталог src/ai_dm/art/ (схема и сейвы не меняются). В-2 — простой режим: **только заставка** при старте
(остальное без рисунков; правка вывода простого режима — сознательная, только титул). В-3 — ASCII + штриховка ░▒▓.
В-4 — рисунок монстра только на первом ходу боя, потом свернуть. В-5 — минимальный набор ≈ 20; все 31 локация — BACKLOG.
