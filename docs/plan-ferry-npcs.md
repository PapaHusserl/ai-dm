# Паром: новые NPC приплывают в Сумеречную Академию (BACKLOG 146)

Контур: вне msa; режим: встроить. План papa-kaban, 2026-10-22; переписан под решение Р1 = А2 (разовый скрипт).
Разведка вариантов (А1/А2/Б/В) — раздел «Рассмотрено», решения — «Решения проектировщика».

## Суть

Проектировщик пишет новых NPC в `campaigns/dusk_academy/npcs.yaml`; в идущем мире `dusk_academy-d3de6c57` они должны
появиться как приплывшие паромом через 1–2 игровых дня от текущего момента, со слухом накануне, и разойтись по своим
местам. Решения проектировщика — тело BACKLOG 146 (2026-10-22) и раздел ниже. Живой сейв у другого человека, у нас
копия от 15 окт. (`saves/dusk_academy-d3de6c57`, слот `auto`: schema v9, `now_s` 21348982 ≈ день 247,
`campaign_version` "1", 9 NPC — 6 пака, 3 от модели). Абсолютный `time_after` вписать нельзя — `now_s` живого мира
неизвестен; его знает только скрипт, запущенный на машине человека, или сама игра при загрузке.

## Что есть в движке (проверено по коду)

- Триггеры живут только в `opportunity` владельцев — NPC, фракция, бог, герой (`world_sim/candidates.py:owners`);
  триггеров уровня мира нет. Фракции и NPC пака догружаются `merge_new` (`campaign/merge.py`) целиком, вместе с
  триггерами; `merge_pack` зовётся при каждой загрузке (`game/app.py:496`, `ui/cli.py:989`).
- `time_after` абсолютный: `world.clock.now_s >= condition.seconds` (`rules/triggers_eval.py:117`). Триггер со
  `state: disabled` движок никогда не трогает: `is_ready` → False (`triggers_eval.py`), в кандидаты и в линию nudge не
  попадает (`nudge.py:33` — только `active`/только что сработавший). В коде `disabled` нигде не ставится — состояние
  есть в модели, но до сих пор не использовалось.
- Граница сцены (`game/boundary.py:finish_boundary`): `check_triggers` → сработавший `then` идёт act-кандидатом в один
  вызов роли world; world исполняет `npc_update` с `location_id` (`protocol/requests.py:733 WorldNpcUpdate`; handler
  берёт NPC по id из `world.npcs`, `handlers/world.py:428` — NPC не обязан быть в контексте) и `world_notice`. Сбой
  world — act откладывается до следующей границы (`world_sim/pending.py`).
- Заметка игроку без LLM — `Notice` в `world.notices` (`state/world.py:237`), прецедент `world_sim/nudge.py:apply_stage`
  ступень 1 (`visibility="rumor"`); `deliver_notices` отдаёт на границе строкой «За кадром: — …». Рассказчик заметок и
  хроники не читает (`master/` — нет обращений к `chronicle`/`notices`).
- Видимость NPC: `master/relevance.py:29 npc_reason_set` — причины `here`/`nearby` (локация), `key`, `said` (имя в
  последних ходах), `merchant`, `active` — по `is_ready(trigger)` без вычисления условия. NPC без локации, без `key`,
  без торговли и без *активных* триггеров рассказчику и роли world не виден. Активный `time_after`-триггер на самом NPC
  сделал бы его видимым и неустранимым (`rank_npcs`) на всё время ожидания парома.
- Прецедент контентной правки одного живого мира: `scripts/migrate_dusk_18plus.py` + `docs/migrate-dusk-18plus.md` +
  `tests/unit/devtools/test_migrate_dusk_18plus.py` (решение Q4б, docs/plan-to.md §9, 2026-10-16): автономный
  stdlib-скрипт, гейт по `world_id` и версиям 9–12, бэкап слота рядом с `slots/`, идемпотентность, отказ без записи.
  Сейвы не в репо (`.gitignore: /saves/`), пак в репо — обновление пака доезжает к человеку через `git pull`.

## План (А2)

Контент — в паке, время — в скрипте. Пак даёт новых NPC без локации и «спящий» триггер прибытия (`state: disabled`,
`time_after: 0` — заглушка «срок задаст скрипт»). Человек делает `git pull`, запускает игру (догрузка добавляет NPC и
триггер — спящий, NPC невидимы), выходит, запускает скрипт: тот читает `clock.now_s`, ставит триггеру
`seconds = now_s + N·86400`, `state: active`, кладёт заметку-слух. Дальше всё делает движок: на первой границе сцены
после срока слуха игрок видит «За кадром: — …», на первой границе после срока парома роль world переставляет NPC и даёт
`world_notice`.

**Правило:** было `time_after` только абсолютным числом в паке → станет: в паке заглушка `time_after: 0` +
`state: disabled`, абсолютное значение и `active` ставит скрипт по `now_s` сейва. Код движка не меняется (при Р2 = б).
**Поведение движка:** не меняется. **Вне репо:** человек с сейвом — `git pull`, запуск игры, скрипт (инструкция
`docs/migrate-dusk-ferry.md`); передаёт проектировщик.

## Развилки и риски (пересмотр под А2)

- **Р1 — решена:** А2.
- **Р2 Владелец спящего триггера:** (а) каждый новый NPC — тогда после скрипта `active` делает их видимыми рассказчику
  на 1–2 дня до парома, нужна правка `relevance.py` (код движка + тесты + mutmut); (б) фракция пака `mainland_ferry`
  (новый `factions.yaml`) — NPC без триггеров невидимы до перестановки, движок не меняется; world переставляет их по id
  из `then` (handler принимает любой id мира). Рекомендую **(б)**: ноль кода движка — в духе «разовой акции». Риск (б):
  world может ошибиться в id → `Invalid`, act уйдёт в `pending` только если не исполнено ничего; смягчение — `then`
  перечисляет id и локации дословно.
- **Р3 Правка видимости** — отпала при Р2 = б (NPC без локации/ключа/триггеров и так не виден); нужна только при Р2 = а.
- **Исполнитель прибытия** (прежняя Р2) — только роль world по `then`: «движок сам» потребовал бы кода в `boundary`,
  что А2 не предполагает. Отпала.
- **Р4 Слух накануне:** (1) скрипт кладёт `Notice rumor` с `deliver_at_s` за `RUMOR_BEFORE_DAYS` до парома — без LLM,
  прецедент nudge; рекомендую; (2) второй спящий триггер фракции `rumor` (`time_after: 0`, скрипт ставит
  `now_s + (DAYS−1)·86400`) → world даёт `world_notice rumor` сам — ещё один вызов world, но слух словами модели.
  Видимое игроку при (1): «За кадром: — <RUMOR_TEXT>» на первой границе сцены после срока; текст — проектировщик.
  Рассказчик о слухе не знает в обоих случаях (заметки ему не передаются) — как у nudge.
- **Р5 Строка догрузки:** при запуске игры после `git pull` человек увидит «Из пака добавлено: faction:mainland_ferry,
  npc:<id>, …» (`game/app.py:merge_pack`) — id новых NPC и фракции раскрываются. (1) оставить — существующее поведение,
  id не имена; (2) скрыть — правка `merge_pack` (код движка). Рекомендую (1). Решает проектировщик.
- **Контент (проектировщик):** N дней (1 или 2), имена/роли/мотивы/`notes`, куда расходятся, тексты `then` и слуха.
- Риски: порядок у человека — «сначала игра, потом скрипт» (скрипт отказывает с подсказкой, если наоборот); если он
  сыграет несколько сцен до скрипта — ничего не ломается, паром отсчитается от момента скрипта. Новые миры с этого пака:
  триггер `disabled` не сработает никогда — NPC в них не приедут (мёртвый контент пака до Р3, см. ниже). Прибытие — на
  первой границе сцены после срока, не посреди сцены. Сейв человека v9–v11 → `load_slot` сам мигрирует до v12 с бэкапом;
  скрипт версию не меняет. Бэкап перед запуском с новым паком — правило AGENTS.md: в инструкции отдельный шаг «скопируйте
  папку `saves/dusk_academy-d3de6c57`» (догрузка сама бэкап не делает — только миграция версии).
