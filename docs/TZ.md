# ТЗ: AI-DM — текстовая RPG в терминале с ИИ-мастером

Статус: v3 — все вопросы груминга мини-влада (2 прохода) закрыты, 2026-10-02

## 1. Суть

Локальное терминальное приложение для одиночной текстовой RPG по механике D&D 5e (ядро SRD).
Повествование ведёт ИИ-мастер (LLM через API), правила и состояние — детерминированный движок.

**Ключевой принцип:** ИИ рассказывает, код считает. Модель никогда не бросает кубики,
не меняет HP/инвентарь напрямую — она возвращает структурированные запросы, движок их
валидирует и применяет.

Граница ответственности:
- **ИИ решает:** повествование; классификацию намерения игрока (какое действие / навык);
  выбор **категорий** (сложность, тип добычи, масштаб награды); выбор действия ключевого NPC /
  напарника из списка, предложенного движком; создание NPC, локаций, зон боя.
- **Движок решает:** все числа (СЛ, урон, добыча, опыт), броски, состояние, допустимость
  запросов, смерть и вывод существ из игры (правило 4.1).

## 2. Модели (LLM)

- Адаптеры провайдеров за единым интерфейсом:
  - **MVP:** Anthropic (Claude), Google (Gemini) — нативные SDK.
  - **Позже:** OpenAI-совместимый адаптер (Ollama / LM Studio / OpenRouter). Интерфейс закладывается сразу.
- Выбор модели — в конфиге и в игре (команда).
- **Роли моделей** настраиваются отдельно:
  - `narrator` — повествование (сильная модель);
  - `world` — проверка триггеров NPC, закадровые события (может быть дешёвой);
  - `summarizer` — выжимки для памяти (дешёвая).
- Протокол «мастер → движок»:
  - MVP: tool calling / structured output (поддерживают и Claude, и Gemini);
  - этап 10: fallback для локальных моделей — свободный текст с размеченными блоками;
  - ответ валидируется; при невалидном — повтор (см. 2.2).
- Протокол с этапа 2 уже содержит `unsupported_action`, флаги, `end_scene` / `end_chapter`,
  даже если обработка части из них появится позже, — чтобы не ломать его на этапах 3–9.
- Бюджет контекста учитывает лимит конкретной модели (см. 11).

### 2.0. Стоимость

- Учёт токенов каждого вызова → деньги по таблице цен из конфига.
- Строка состояния — стоимость текущей сессии; `/cost` — разбивка по ролям/моделям,
  за сессию / день / мир.
- Лимита по умолчанию нет; механизм мягкого лимита (сессия/день — день общий для всех миров, по местному времени; предупреждение на 80%,
  пауза с выбором на 100%) закладывается, но выключен.
- Экономия:
  - кэширование постоянной части промпта (правила, мир, истины — в начале промпта);
  - один пакетный вызов `world` на границе сцены на все нарративные условия, у которых
    уже выполнена структурная часть;
  - скачок времени — один вызов `world` на игровой год + один итоговый вызов на хронику.

### 2.1. Запросы мастера к движку (закрытый список, детали — архитектор)

Общее правило: **ИИ только предлагает, финальное слово за движком.** Запрос за пределами
лимитов урезается (не отклоняется) + авто-репорт.

| Группа | Запросы |
|---|---|
| Проверки | `skill_check`, `saving_throw` (ИИ выбирает навык и **категорию** сложности, опц. `stakes: critical`; движок переводит в СЛ и бросает) |
| Бой | `start_combat` (состав, зоны, намерения врагов), `player_action` (классификация фразы игрока + импровизированный эффект), `npc_action` (выбор действия напарника / ключевого NPC из списка движка), `defeat_outcome` (1–2 последствия из таблицы 5.1), `end_combat` |
| Ресурсы | `damage` вне боя (по тяжести), `give_item` / `take_item`, `gold`, `award_xp` (ИИ указывает повод, объём — по таблице движка) |
| Мир | `advance_time`, `rest` (длинный -- с `prepared_swap`: смена подготовленных), `warn_danger`, `set_flag`, `npc_create`, `location_create`, `npc_update`, `favor_change`, `reveal_secret`, `event_start` / `event_end` (глобальные события 4.1.2, только с `cause`) |
| Сцена | `offer_choices`, `end_scene`, `end_chapter` |
| Посмертие | `afterlife_action` (тип: короткое / долгое / эпическое — движок проверяет по списку 5.1) |
| Служебное | `unsupported_action` (→ авто-репорт) |

**Исключения из «урезается, не отклоняется»** — эти запросы **отклоняются** с сигналом мастеру:
- смерть / вывод существа без причины по правилу 4.1 (`npc_update(status=dead|gone)`) → авто-репорт `invalid-death`;
- `npc_create` / `location_create` с нарушением уникальности (5.3);
- `reveal_secret` при невыполненном условии раскрытия (4);
- `event_start` войны / чумы без `cause` (сработавший триггер NPC, фракции или бога) — 4.1.2.

### 2.2. Ошибки и недоступность API

- Сеть / таймаут / rate limit: 3 повтора с нарастающей паузой (1 → 3 → 10 с).
- Невалидный ответ: до 2 повторов с пояснением модели, что не так (несуществующий NPC,
  неверный формат и т.п.).
- Не помогло → **откат хода** и выбор игрока: повторить / переключить модель / сохранить и выйти.
- Автоматического переключения модели нет — только по выбору игрока. Исключение — серверный fallback при отказе
  модели: флаг в конфиге, по умолчанию выключен (решение проектировщика, этап 2).
- Отказ модели (фильтры провайдера) → тот же выбор + подсказка сменить модель или `tone`
  + авто-репорт `refusal`.
- **Атомарность хода:** состояние применяется только после успешного завершения всего хода.

### 2.3. Пределы для ИИ

- **СЛ:** ИИ выбирает категорию (очень лёгкая … почти невозможная), движок переводит в СЛ 5/10/15/20/25/30.
- **Добыча, золото, магические предметы:** таблицы сокровищ SRD; добыча с врагов — только по побеждённым в последнем бою, по их ПО; расходники — лимит за сцену (конфиг); ИИ задаёт тип
  («добыча с бандита», «клад логова»). Редкость магпредметов ограничена уровнем.
- **Опыт:** за бой — формула 5e по опасности **всех побеждённых** врагов (убиты, выбыли, сбежали, сдались); при поражении героя опыта нет; за квесты/находки ИИ называет масштаб
  (мелкий/средний/крупный), движок даёт долю опыта до следующего уровня: 10% / 25% / 50% (в конфиге).
- **Урон вне боя** (ловушки, падения, огонь, яд): ИИ выбирает тяжесть, движок бросает:

  | Уровень героя | Неприятность | Опасно | Смертельно |
  |---|---|---|---|
  | 1–4 | 1d10 | 2d10 | 4d10 |
  | 5 | 2d10 | 4d10 | 10d10 |

  Смертельный урон — только после проваленного спасброска/проверки.
- **Лечение вне боя** — только через механику: отдых, заклинания, зелья, услуги лекаря.
  Свободного `heal` от мастера нет.
- **Бой:** движок проверяет бюджет сложности по уровню героя и напарников и сложности кампании (`easy/normal/hard`, команда `/difficulty`). Бой сверх бюджета
  разрешён, если выполнено хотя бы одно:
  - ранее был `warn_danger` (флаг на локацию/угрозу: следы, кости, предупреждения);
  - герой сам напал на заведомо сильного противника;
  - сработал триггер NPC с целью убить героя.

  Иначе состав урезается до бюджета (с сигналом мастеру, см. ниже).
- **Превышение лимита:** движок урезает → **сигнал мастеру** (доп. вызов модели), мастер
  подстраивает описание под фактический результат → авто-репорт.

## 3. Кампании (паки)

Движок и кампания разделены. Точка инициализации — вне игры.

```
campaigns/<campaign_id>/
  campaign.yaml     — метаданные, tone (ограничения контента), стартовые условия
  world.md          — мир, история, атмосфера
  truths.md         — неизменные факты мира (опционально)
  npcs.yaml         — ключевые NPC (мотив/средства/возможность)
  factions.yaml     — фракции (тот же формат)
  pantheon.yaml     — боги (см. 4.2)
  locations.yaml
  character.yaml    — готовый герой (опционально)
```

- Сеттинг: **только фэнтези**.
- Команда `import`: текстовая выжимка (например, из сессии Антигравити) → ИИ раскладывает
  её по файлам пака → пользователь правит руками.
- `tone` задаётся в паке и **меняется по ходу игры** командой (`/tone`), сохраняется в сейв:

  ```yaml
  tone:
    mood: мрачный             # героический | мрачный | приключенческий | комедийный | …
    violence: реалистично     # мягко | реалистично | жестоко
    horror: умеренно          # нет | умеренно | сильно
    romance: намёки           # нет | намёки | чувственно | откровенно (решение 2026-10-08; сам акт — всегда за кадром)
    language: грубо           # сдержанно | грубо
    hard_limits: [насилие над детьми]   # никогда
    soft_limits: [пытки]                # только за кадром
  ```

  - `/tone` может менять всё; ослабление `hard_limits` — с подтверждением.
  - Изменения тона пишутся в хронику мира.
  - Политики провайдеров моделей `tone` не отменяет; отказы обрабатываются по 2.2.
- Одну кампанию можно проходить многократно: новым миром или продолжением мира с наследником (см. 5.2).

## 4. Сюжет: NPC-driven (мотив / средства / возможность)

Сюжет не строится из заготовленных сцен — его двигают персонажи с собственными целями.
Подход: https://longstoryshort.app/long/motive-means-opportunity/

Карточка NPC / фракции:

```yaml
- id: mentor_aldric
  name: Олдрик
  motive: Избавить сестру от вампиризма любой ценой      # одно сильное желание
  means:                                                  # 1–3 средства
    - Знание запретной магии крови
    - Долг гильдии воров перед ним
  opportunity:                                            # условия «если — то», формат см. 4.01
    - id: steal_grail
      if: {hero_has: blood_grail}
      then: попробует выкрасть его, подставив героя
      once: true
  status: alive            # alive | dead | gone | changed
  attitude: 20             # отношение к герою
  known_to_player: [...]
  secrets: [...]
  combat: {...}            # боевой блок (опционально)
```

- Якоря (ключевые NPC и их цели) **можно провалить или пропустить**: мёртвый NPC не
  срабатывает, сюжет перестраивается из мотивов остальных.
- **Ход мира:**
  - игровое время (дни, время суток, путешествия);
  - после каждой сцены — проверка триггеров `opportunity`: простые (по флагам) — движком,
    сложные — моделью роли `world`;
  - сработавший триггер → событие: видимое сразу или отложенное (слухи, последствия);
  - мягкое подталкивание игрока, если он долго вне основных линий:
    - основные линии = активные триггеры ключевых NPC / фракций / богов (`key: true` в паке) + мотив героя;
    - «долго» = больше N сцен (по умолчанию 8) без соприкосновения с основной линией
      (ключевая сущность в сцене или изменение связанного флага);
    - ступени: слух → контакт (NPC сам выходит на героя) → событие находит героя;
    - после третьей ступени мир **перестаёт ждать**: NPC добиваются целей без героя.
- Новые NPC / локации, созданные ИИ на лету, сохраняются в состояние в том же формате.
- **Секреты NPC:**
  - нарратор видит секреты только NPC текущей сцены, с пометкой «скрыто: играй с учётом,
    оставляй намёки, не раскрывай»;
  - у каждого секрета — условие раскрытия (формат как у триггеров, 4.01);
  - раскрытие — только запросом `reveal_secret(npc, secret)`; движок проверяет условие,
    при невыполнении отклоняет с сигналом мастеру «ещё рано»;
  - раскрытый секрет переходит в `known_to_player`.

### 4.00. Время (этап 1)

- Движок ведёт игровые часы и календарь.
- Механические действия — время считает движок: раунд боя 6 с, короткий отдых 1 ч,
  длинный 8 ч, путешествие — по расстоянию между локациями.
- Нарративные скачки — мастер через `advance_time` с категорией
  (минуты / часы / день / неделя / месяц), движок переводит в конкретное значение:
  минуты = 15 мин, часы = 1 ч (не закрывает сцену), день, неделя = 7 дней, месяц = длина месяца календаря.
- Страховка: если за сцену время не сдвинулось — движок добавляет минимум (~10 мин, в конфиге).
- Календарь (месяцы, длина года, праздники богов) задаёт пак; нет — стандартный календарь 12 × 30 (Заревень … Темнозим).

### 4.01. Формат триггеров (этап 1 — схема)

```yaml
opportunity:
  - id: steal_grail
    if:
      all:                                  # all / any / not
        - hero_has: blood_grail
        - npc_status: {id: mentor_aldric, is: alive}
    then: Выкрасть Грааль, подставив героя перед гильдией
    once: true                              # или cooldown: 7d
  - id: sister_secret
    if:
      narrative: Герой узнаёт, что сестра Олдрика — вампир
    then: Убедить героя помочь, при отказе — устранить
```

- **Структурные условия** — проверяет движок (детерминированно, бесплатно):
  `flag`, `hero_has`, `npc_status`, `hero_at` / `npc_at`, `time_after`, `attitude`, `favor`,
  `event_active`, `hero_dead`. Список расширяемый.
- **Нарративные условия** (`narrative`) — проверяет модель роли `world` на границе сцены.
  В смешанных условиях модель вызывается, только если структурная часть уже выполнена.
- **`then`** — текст намерения; при срабатывании мастер / `world` превращает его в обычные запросы к движку.
- **Флаги ставят:** движок автоматически (получен предмет, NPC умер, посещена локация, бой
  завершён), мастер (`set_flag`), пак (стартовые).
- ИИ при создании NPC на лету и при `import` предпочитает структурные условия; движок
  проверяет, что ссылки указывают на существующие id.

### 4.0. Сцена и глава

- **Сцена** — непрерывный эпизод в одном месте/времени с одной задачей.
  - Закрывает мастер (`end_scene`), когда эпизод исчерпан.
  - Страховка движка — принудительное закрытие: смена локации; скачок времени > 1 часа;
    конец боя; > N ходов игрока (N≈30, в конфиге).
- **Граница сцены:**
  1. автосейв закрытой сцены;
  2. **обязательно перед стартом новой сцены:** выжимка сцены + проверка триггеров (NPC,
     фракции, боги, события, случайности). Без них новая сцена не стартует; при сбое —
     обработка ошибок 2.2 (повторы → повторить / сменить модель / сохранить и выйти);
  3. закадровый блок — **только если есть заметное герою событие**.
- **Глава** — единица памяти и сюжета, имеет название («Глава 3: Предательство Олдрика»).
  - Мастер шлёт `end_chapter` при значимом повороте (срабатывание триггера ключевого NPC/бога и т.п.).
  - Страховка: принудительное закрытие после 15 сцен (в конфиге).
  - При закрытии выжимки сцен сворачиваются в выжимку главы.

### 4.1. Правило «у смерти есть причина»

NPC и герой подчиняются одним правилам. Существо может умереть / быть выведено из игры
(плен, изгнание, увечье) **только** через одну из четырёх причин:

1. **Чью-то цель** — сработавший триггер другого NPC/фракции/бога или действие игрока.
   Резолвится механикой (бой, проверки), не решением ИИ.
2. **Опасность** — скользкий обрыв, яд, пожар → спасбросок/проверка по характеристикам
   существа. За кадром — тем же броском движка.
3. **Абсолютную случайность** — базовый шанс за игровой день задаётся паком (`mortality`, см. 4.1.1).
   Бросает только движок; ИИ лишь описывает результат.
   Покровительство богов даёт шанс «отвести беду» (переброс, см. 4.2).
   - Действует на именованных NPC и героя; безымянная массовка поштучно не отслеживается.
   - В посмертии не действует.
   - При скачке времени — один бросок на существо за игровой год с эквивалентной годовой вероятностью.

4. **Старость** — естественная причина.
   - Продолжительность жизни по расе (SRD): человек ~60 / ~90, полурослик ~100 / ~150,
     дварф ~250 / ~350, эльф ~500 / ~750 (порог старости / предел).
   - После порога — проверка естественной смерти раз в игровой год, шанс растёт к пределу до ~100%.
   - После порога — механические минусы (−1 к СИЛ/ЛОВ/ТЕЛ за каждые 10% предела жизни расы, в конфиге): меняются «средства» NPC.
   - Благосклонность богов от старости **не защищает**. Продление жизни — только по явной сделке
     с богом (триггер с ценой) или как мотив NPC (бессмертие, личинство).

#### 4.1.1. Смертность мира

Пресеты `mortality` (или точное значение):

| Пресет | В день | ≈ в год |
|---|---|---|
| Спокойный | 1/500 000 | 0,07% |
| Мирный | 1/50 000 | 0,7% |
| **Обычный (по умолчанию)** | 1/20 000 | 1,8% |
| Суровый | 1/5 000 | 7% |
| Жестокий | 1/500 | 52% |

#### 4.1.2. Глобальные события

Голод, чума, война и др. — сущность мира:

```yaml
- id: grey_plague
  type: plague              # famine | plague | war | … (расширяемо)
  regions: [порт_вейл, нижний_город]
  affects: [все]            # или группы: бедняки, солдаты, старики…
  mortality_multiplier: 20  # базовый шанс × N для тех, кто в зоне и в группе риска
  hazard: {save: ТЕЛ, dc_category: средняя}   # прямой контакт → отдельный бросок (4.1 п.2)
  started: 1247-03-12
  ends_when: …              # срок или условие
  cause: god:morrah
```

- **Война и чума** возникают только из мотивов NPC, фракций и богов (срабатывание триггера).
- **Природные события** (голод, засуха и т.п.) — также из последствий (сожжённые амбары, осада)
  либо случайным броском мира раз в игровой сезон; частота — в настройках пака, по умолчанию редко.
- Пак может задать события на старте («кампания начинается в разгар войны»).
- События порождают триггеры NPC в зоне (купец наживается на голоде и т.п.).

Запрос ИИ на смерть/вывод NPC без одной из причин отклоняется + авто-репорт.

### 4.2. Боги и благосклонность (этап 3)

- Пантеон — в паке (`pantheon.yaml`). Бог — NPC-подобная карточка: домены, мотив,
  `pleased_by`, `angered_by`, соперники (`rivals`), средства, возможности (`if — then`).
- Благосклонность: шкала **−10..+10** у каждого существа (герой и NPC) к каждому богу.
  - Меняется запросом ИИ `favor_change(бог, сдвиг, причина)`; движок ограничивает шаг (±2 за поступок).
  - Угодить богу может значить разгневать его соперника.
- Эффекты по порогам (зеркально для отрицательных):
  - +3 — знамения, сны;
  - +6 — раз в день преимущество в критический момент;
  - +9 — божественное вмешательство (спасение от смерти → бог потом требует услугу).
  - −3 / −6 / −9 — дурные знамения, помеха, проклятие / слуги бога охотятся на героя.
- Защита от случайной смерти: при выпадении — проверка **самого благосклонного** бога,
  шанс отвести беду = благосклонность × 10% (+10 → 100%).
- **Критический момент** (для +6 / −6) определяет движок: спасброски от смерти, спасброски от
  эффектов, способных убить/вывести из игры, проверки с пометкой мастера `stakes: critical`.
  - +6: раз в день преимущество, активирует **игрок** молитвой;
  - −6: первый критический бросок за день — с помехой автоматически.
- **Вмешательство** (+9) при неминуемой смерти: шанс 50% (+9) / 75% (+10), не чаще раза за главу.
  После спасения бог выставляет услугу (триггер-долг); пока не выполнена — благосклонность заморожена.
  −9: у бога-врага появляется триггер «послать слугу».
- Лимиты изменения: ±2 за поступок, ±3 к одному богу за сцену. Благосклонность NPC меняет ход
  мира (роль `world`) с теми же лимитами.
- Боги участвуют в ходе мира (их триггеры проверяются реже, действуют через слуг, знамения, культы).
- **Жрец** — сила привязана к своему богу:

  | Благосклонность своего бога | Эффект |
  |---|---|
  | > −3 | норма |
  | ≤ −3 сомнение | заклинание 1+ круга → проверка МДР (СЛ 10), провал — ячейка потрачена впустую |
  | ≤ −6 отчуждение | Божественный канал недоступен; ячейки высшего круга не восстанавливаются |
  | ≤ −9 отлучение | только заговоры до квеста искупления |

  Смена бога (к сопернику) — через сделку/квест, стартовая благосклонность у нового +1.
  На этапе 1 жрец собирается без этой механики (точка расширения — модификатор сотворения).
- Игрок видит благосклонность **приблизительно**: «благосклонна / равнодушна / гневается».
- В движке этапа 1 закладывается только точка расширения: модификаторы бросков и перебросы.

## 5. Персонаж

- Герой-одиночка.
- Источники: импорт из пака / создание на лету.
- Создание на лету:
  - игрок описывает героя словами → ИИ предлагает лист по правилам → движок валидирует → игрок подтверждает/правит;
  - альтернативно — пошаговый классический режим.
- Герою тоже задаются мотив / средства / возможности (крючки для мастера).

### 5.1. Поражение и смерть

Смерть — не конец игры, но конец сюжета конкретного героя.

1. **0 HP — решают мотивы врагов.**
   - При `start_combat` ИИ задаёт каждому врагу/группе **намерение при победе**:
     `kill` / `capture` / `rob` / `drive_off` / `spare`. Хранится в состоянии боя.
     Для смешанной группы действует намерение лидера.
   - Рядовые враги — движок применяет намерение напрямую. Ключевой NPC может передумать
     в момент падения героя (ситуация выбора мастером, раздел 7).
   - Не `kill` → **поражение с последствиями**: ИИ выбирает 1–2 из фиксированной таблицы,
     движок применяет числа:

     | Последствие | Механика |
     |---|---|
     | Плен | герой в локации врага, снаряжение изъято → сцена побега/переговоров |
     | Ограбление | −50% золота + 1–2 ценных предмета, **кроме надетого** (выбирает движок; % — в конфиге) |
     | Брошен умирать | очнулся через 1d8 часов с 1 HP (в конфиге) |
     | Шрам | постоянный минус (−1 к характеристике или помеха на навык) + описание |
     | Истощение | +1 уровень |
     | Долг | услуга спасителю/пленителю (флаг + триггер NPC) |

   - `kill` / опасность / случайность → спасброски от смерти по 5e.
     Возможны: стабилизация напарником, вмешательство бога (+9), передумавший враг.
   - **Временное правило этапов 2–7** (до посмертия): смерть героя → загрузка последнего сейва.
   - Смерть героя **не обрывает бой**: если союзники стоят, бой продолжается; итог боя — `hero_dead`
     (даже при победе союзников), тело остаётся у союзников (оживление — этапы 7–8).
   - Враг не хочет убивать → упавший герой сразу стабилен, спасброски от смерти не бросаются.
2. **Смерть → посмертие.**
   - **Чья душа:** бог с наибольшим **модулем** благосклонности.
     - благосклонный — забирает как своего (посмертие легче, бог может помогать);
     - гневный — как добычу (посмертие тяжелее, Нить истончается быстрее);
     - ничья → **спор богов**: сцена, d20 + модуль за каждого, герой может повлиять
       (молитва, обещание, предательство);
     - модуль < 3 у всех → нейтральное посмертие: бог смерти пантеона (`role: psychopomp`)
       или «Серые Пределы» по умолчанию (генерирует ИИ);
     - жрец при равенстве — к своему богу без спора (отлучённый — как добыча).
   - Посмертие — играбельный реалм: локации, NPC (в т.ч. умершие), свои правила.
   - Описание реалма опционально в паке; если его нет — ИИ генерирует по доменам бога.
   - Мир живых продолжает ход.
3. **Пути назад:**
   - изнутри: квест, сделка с богом, побег;
   - снаружи: триггеры живых NPC (`if: герой мёртв`) — воскрешение, ритуал, кража реликвии.
     Резолвятся механикой хода мира, могут провалиться или дорого стоить самому NPC;
   - возвращение — в изменившийся мир, с меткой посмертия (долг богу, шрам души, знания).
4. **Время и «Нить памяти».**
   - В посмертии нельзя погибнуть, но время течёт иначе: каждое долгое действие (партия с богом,
     поиск выхода, служба) стоит лет в мире живых и истончает Нить памяти.
   - **Нить = 6** (в настройках кампании); +1, если мотив героя связан с живым NPC;
     −1, если душу забрал гневный бог.
   - Действия классифицирует мастер, движок проверяет по списку:

     | Тип | Примеры | Время в мире живых | Нити |
     |---|---|---|---|
     | Короткое | разговор, осмотр, переход | 1d4 недели (в конфиге) | 0 |
     | Долгое | шаг квеста выхода, служба богу, поиск пути | 1d10 лет | 1 |
     | Эпическое | партия с богом, испытание души | 3d10 лет | 2 |

     Побег, сделка и служба богу — всегда долгие или эпические.
   - Поддержка снаружи: пока активен триггер воскрешения у живого NPC — каждое второе
     долгое действие не тратит нить.
   - Потери по мере истончения (мастер описывает изнутри):
     - ≤ 4 — детали: второстепенные NPC исчезают из знаний героя (в листе — *забыто*);
     - ≤ 2 — связи: герой играется безразличным к живым (числа `attitude` NPC не меняются);
     - 0 — мотив → **окончательная смерть героя**.
   - **Бой в посмертии:** HP — временная «форма» души, полностью восстанавливается перед
     каждым боем; ставка — Нить: **проигрыш стоит 1d6 нитей**.
5. **Судьба растворённого героя** — на усмотрение бога и сюжета (обязательно вписывается в историю):
   растворение / NPC-марионетка бога / **вознесение в бога** (новый член пантеона — пантеон
   является изменяемой частью состояния мира, а не только пака). Пути вознесения:

   | Путь | Условие | Результат |
   |---|---|---|
   | Избранник | благосклонность +10 к забравшему богу + бог предлагает сделку | младшее божество на службе покровителя |
   | Культ | живые последователи (основатель — NPC с attitude ≥ 60) достигают порога веры за время героя в посмертии | самостоятельное младшее божество, сила растёт с культом |
   | Узурпация | эпическое действие против бога в посмертии (почти невозможные проверки) | забирает домен поверженного |

   Вознёсшийся: домены — по жизни и поступкам; мотив — прежний, преобразованный; отношения
   с пантеоном; сразу участвует в ходе мира (может покровительствовать наследнику).

### 5.2. Наследие: следующий герой

Мир живёт независимо от героев.

1. Игрок называет концепцию нового героя (сын, ученик, мститель, не связанный) → ИИ предлагает
   длину скачка времени → игрок подтверждает.
2. **Скачок времени:** движок прогоняет ход мира в ускоренном режиме (триггеры, случайности,
   старение), ИИ пишет хронику по мотивам NPC и фракций.
3. Новый герой начинает с **1 уровня** в том же мире: NPC помнят прошлого героя, флаги и
   смерти сохраняются.
   - `attitude`: NPC, знающий о связи наследника с прежним героем, начинает с 50% отношения
     к прежнему; не знающий — с 0 до раскрытия связи.
   - **Реликвии** прежнего героя остаются в мире (место гибели, у победителя, у мародёров).
     Магпредмет выше доступной по уровню редкости «спит»: свойства пробуждаются по достижении уровня.
4. Сохранения делятся на мир и героев:

```
saves/<world_id>/
  world/        — NPC, фракции, пантеон, флаги, время, хроника
  heroes/
    01_<name>/  — завершён (судьба записана)
    02_<name>/  — текущий
```

**Режимы старта:**

| Режим | Что происходит | Откуда герой |
|---|---|---|
| Новый мир | мир разворачивается из пака с нуля | `character.yaml` пака или создание на лету |
| Продолжить мир | тот же мир после скачка времени, с наследием | только создание на лету (концепция + связь) |

- `character.yaml` пака используется только в новом мире.
- Продолжение доступно после окончательной смерти героя **или** если живой герой
  **уходит на покой**: становится NPC (наставник, правитель, отшельник) с мотивом и
  возможностями, а новый герой может с ним встретиться.

### 5.3. Совместимость сейвов и паков

- В каждом сейве — версия схемы. Изменение формата сопровождается **миграцией**; при загрузке
  старый сейв обновляется автоматически, перед миграцией делается резервная копия.
- Правило разработки: патч, меняющий формат сейва, не принимается без миграции и теста на неё.
- Схема сейва с этапа 1 вмещает мир, NPC, пантеон, память, `tone`, хронику — даже если
  сами механики появятся позже.
- Правки пака в уже идущем мире: **новые** сущности (NPC, локации, боги, фракции) добавляются
  при загрузке; изменения существующих сущностей не применяются (мир живёт своей версией).
- **Уникальность сущностей:**
  - **id** уникальны всегда — единое пространство для NPC, фракций, богов, локаций и героев;
  - имена именованных NPC не совпадают с именами героев;
  - **имена** уникальны у именованных NPC, богов и фракций (герои и персонажи не повторяются);
  - **имена локаций** уникальны в пределах родительской локации («Таверна» в Вейле и в столице — можно);
  - сущность пака, нарушающая уникальность, не загружается — игроку показывается список
    конфликтов, сущность нужно переименовать (новое имя и id);
  - ИИ при `npc_create` / `location_create` с нарушением уникальности получает отказ и
    придумывает другое.

## 6. Механика (ядро SRD 5e)

- Редакция: **SRD 5.2** (правила 2024), CC-BY-4.0 → атрибуция в `LICENSE`.
  Терминология — устоявшаяся из перевода 2014 / dnd.su, новые термины — в собственный глоссарий.
- 6 характеристик, модификаторы, бонус мастерства, навыки, спасброски.
- Классы: воин, плут, жрец, волшебник, следопыт.
- Расы: человек, эльф, дварф, полурослик.
- **Предыстории — свободные, нарративные.** Игрок описывает предысторию словами → ИИ раскладывает
  на механику по структуре 5.2 → движок валидирует: 3 связанные характеристики (+2/+1 или +1/+1/+1),
  2 навыка, 1 инструмент, 1 черта происхождения, стартовое снаряжение/золото.
  Бюджет стартового снаряжения + золота — **50 зм** по ценам предметов (как у предысторий SRD).
  4 предыстории SRD (прислужник, преступник, мудрец, солдат) — примеры для модели.
- Характеристики: стандартный набор, покупка очков или свободный ввод (3..20, после бонуса ≤ 20) —
  все три доступны и при создании на лету.
- Навык класса, совпавший с навыком предыстории, — ошибка «выбери другой».
- Повтор черты (например через Versatile человека) — только для черт со свойством Repeatable по SRD.
- **Подклассы** (3-й уровень): движок поддерживает формат подкласса как данные; наполнение — в
  каталоге `content/` или в паке (свои, официальные для личного использования, от сообщества).
  Репозиторий движка содержит только SRD-подкласс + 1–2 собственных на класс (свободный контент).
  SRD: воин — Чемпион, плут — Вор, жрец — Домен жизни, волшебник — Воплощение, следопыт — Охотник.
- Черты: черта происхождения — из предыстории; на 4-м уровне — +2 к характеристикам или черта из SRD/`content/`.
- Мастерство оружия (5.2).
- Уровни 1–5, опыт. HP при повышении уровня — выбор игрока: среднее (по умолчанию) или бросок кости хитов.
- Заклинания: заговоры и 1–3 круг для жреца и волшебника (10–12 на класс), 1–2 круг для
  следопыта; ячейки, отдых (короткий/длинный). Подготовленные заклинания игрок выбирает явно.
- Снаряжение: базовое оружие и доспехи SRD + ~10 зелий/расходников. Инвентарь, золото.
- Состояния: все из SRD.
- Монстры: 20–30 из SRD, ПО 0–5; пак может добавлять своих.
- Кубики — **автоматически**, все броски видны в логе: `d20 (14) + 5 = 19 vs КД 15 → попадание`.
- Расширение — патчами по мере игры (см. раздел 9).

## 7. Бой (смешанный)

- Структура тактическая: инициатива, раунды, действие / бонусное действие / движение, HP, КД, состояния.
- Бой изначально рассчитан на нескольких участников с каждой стороны (герой + напарники vs враги).
- **Пространство — зоны:**
  - поле боя = 2–5 именованных зон («у двери», «центр зала», «балкон»), каждая со своими особенностями
    (высота, укрытие, скользко, огонь);
  - в одной зоне — вплотную (ближний бой, провоцированная атака при выходе);
  - соседняя зона — близко; через одну и дальше — далеко;
  - перемещение = в соседнюю зону, рывок = на две;
  - заклинания по площади накрывают зону (крупные — несколько);
  - зоны и их особенности предлагает ИИ при `start_combat`, движок проверяет формат и связность;
  - особенности зон — топливо для импровизации («обрушиваю люстру на центр зала»).
  - перевод дальностей:

    | Дистанция | ≈ футы | Что работает |
    |---|---|---|
    | Та же зона | до 10 | ближний бой, досягаемость, «касание» |
    | Соседняя зона | до 30 | метательное оружие, заклинания до 30 фт |
    | Через одну и дальше | до 120 | луки, арбалеты, большинство заклинаний |
    | За пределами поля | > 120 | длинные луки на дальней дистанции |

    обычная дистанция оружия — без штрафа, дальняя — с помехой; дальняя атака при враге в той же
    зоне — с помехой; площадь радиусом до 20 фт = одна зона, больше — зона + соседние.
- Ввод свободный: ИИ раскладывает фразу игрока на механику.
  - Стандартные действия (атака, заклинание, предмет, отход, уклонение, помощь) — напрямую движком.
  - Импровизация → проверка навыка (категория сложности, см. 2.3) + эффект из
    **фиксированного набора**: преимущество, сбить с ног, доп. урон, оттолкнуть (в зону ниже — падение), обезоружить.
  - Граница с `unsupported_action`: если намерение игрока укладывается в набор — мастер обязан
    выбрать эффект из набора; если ни один эффект не передаёт суть (захват, верховой бой) —
    ближайший эффект из набора + `unsupported_action` (авто-репорт).
- **Управление участниками (гибрид):**
  - рядовые враги — тактика движка, ИИ только описывает;
  - напарники и ключевые NPC (боссы, NPC из пака) — по умолчанию тактика движка, но мастер (ИИ)
    выбирает действие из списка доступных движку, когда:
    - игрок отдал приказ напарнику → мастер решает, выполнит ли (бросок по `attitude`) и как;
    - срабатывает черта характера / триггер (при смерти, появился заклятый враг, низкое
      `attitude` → шанс сбежать или предать, проигрывающий злодей решает отступить/торговаться).

- Уточнения проектировщика (приёмка этапа 1):
  - бегство — только из зоны с выходом, тратит действие;
  - опасная зона: провал спасброска — полный урон, успех — 0;
  - встать после падения — всё перемещение хода;
  - тактика врагов: лучник стреляет, если рядом нет врага; лежащего героя добивают только при намерении `kill`.

## 8. Напарники

- Появляются по сюжету, управляются мастером. Максимум 1–2 одновременно.
- Напарник = NPC-карточка + боевой блок.
- Игрок может отдавать приказы; напарник не обязан подчиняться. В бою — гибридное управление (см. раздел 7).
- `attitude` меняется от поступков героя; из-за собственного мотива напарник может уйти,
  поставить условие или предать.

### 8.1. Шкала `attitude` (отношение NPC к герою)

| Диапазон | Отношение | Возможно |
|---|---|---|
| ≥ 60 | преданность | рискнёт жизнью, выполнит почти любой приказ |
| 20…59 | дружба | помогает, делится информацией |
| −19…19 | нейтралитет | действует по своим интересам |
| −59…−20 | неприязнь | напарник может уйти / поставить условие |
| ≤ −60 | вражда | может предать или напасть, если совпадает с мотивом |

- Диапазон −100…+100; шаг ≤ ±10 за поступок, ≤ ±20 за сцену.
- Приказ напарнику: шанс = 50% + attitude/2; опасный приказ −20%; приказ против мотива
  напарника не выполняется, если отношение ниже преданности.
- Игрок видит приблизительно: предана / дружелюбна / насторожена / враждебна.
- Отношения NPC между собой — текстом в карточках (без чисел), опора для мотивов и триггеров.

## 9. Ищью-репорты

Цель — дорабатывать игру патчами по реальному опыту.

- **Ручной:** `/report <текст>`.
- **Автоматический:** метки
  - `missing-mechanic` — `unsupported_action` в протоколе мастера (мастер выкручивается
    нарративно, игра не останавливается);
  - `limit-exceeded` — запрос ИИ урезан движком (2.3);
  - `invalid-death` — запрос смерти без причины (4.1);
  - `refusal` — отказ модели (2.2);
  - `refusal_retry` — ход повторён после отказа (при повторном отказе теги идут в порядке `["refusal_retry", "refusal"]`); `summarizer_backup` (до #22 `refusal_fallback`) — запасная выжимка после отказа или невалидного ответа (`refusal`/`invalid`) summarizer; `summary_trimmed` — выжимка длиннее предела обрезана движком по границе предложения (после `[memory] summary_trim_after` переполнений); `world_skipped` — вызов world на границе пропущен при мягком сбое (`refusal`/`invalid`/`network`), кандидаты `verdict` уйдут на следующую границу.
- Репорт — markdown-файл в `issues/` с контекстом для воспроизведения:
  текст, последние N ходов, снимок состояния, **сид и состояние RNG**, модель, сырой запрос/ответ.
- API-ключи в репорты не попадают.
- Позже (опц.) — отправка в GitHub Issues.

## 10. Интерфейс

- TUI (Textual): панель сцены, лист персонажа, лог бросков, поле ввода.
- Fallback — простой построчный режим.
- Ввод: свободный текст + мастер иногда предлагает 2–3 варианта (особенно в бою и диалогах).
- Язык — **только русский** (интерфейс, повествование, паки). Другие языки не требуются.
- Служебные команды: `/save`, `/load`, `/model`, `/tone`, `/cost`, `/report`, `/sheet`, `/inv`,
  `/retire` (уйти на покой, 5.2), `/help`.

## 11. Сохранения и память

- Автосейв на границе сцены (4.0), при создании мира и при выходе из игры + ручные слоты; хранится N последних автосейвов (конфиг, по умолчанию 3). Структура «мир + герои» — см. 5.2, совместимость — 5.3.
- RNG с сидом, состояние RNG — часть сейва.
- **Журнал вызовов модели** (обязательно): роль, запрос, ответ; хранится рядом с сейвом с
  ограничением размера (старое сжимается/удаляется).
- **Режим воспроизведения:** сид RNG + ответы из журнала вместо живых вызовов → точное
  повторение хода. Репорт содержит нужный фрагмент журнала.
- Кампании долгие → иерархическая память мастера:
  выжимка сцены → выжимка главы → выжимка всей игры.
- В контекст мастера: world/truths + релевантные NPC/локации + выжимки + последние ходы + состояние.
- **Бюджет контекста:**
  - никогда не выкидываются: правила протокола, состояние героя и сцены, истины мира, NPC текущей сцены;
  - при переполнении выкидываются по порядку: старые сырые ходы → выжимки старых сцен
    (остаются выжимки глав) → неактивные NPC и локации;
  - релевантные NPC: в сцене, упомянутые в последних ходах, связанные с текущей локацией,
    с активным триггером;
  - `/model` посреди игры разрешён — бюджет пересчитывается под лимит новой модели.
- **API-ключи:** из переменных окружения (`ANTHROPIC_API_KEY`, `GEMINI_API_KEY`) или `.env`
  в папке игры (`.env` — в `.gitignore`). Ключи никогда не пишутся в сейвы, журнал и репорты.

## 12. Стек

**Жёсткие ограничения:** Python 3.12+, Textual (TUI), Pydantic (модели/валидация),
SDK `anthropic` и `google-genai`, pytest, `uv` (установка: `uv tool install` / `uv run`).

Платформы: macOS и Linux; Windows не обещаем, но намеренно не ломаем.

Всё остальное — раскладка модулей, формат хранения состояния, имена файлов внутри пака
и сейва, реализация механизма повторов (политика — в 2.2) — решает архитектор. Пути и YAML-примеры в ТЗ иллюстративны.
