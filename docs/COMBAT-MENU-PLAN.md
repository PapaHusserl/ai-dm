# Партия «Меню боя: сначала цель» — план (папа-кабан, 2026-10-06, на утверждение)

Основание: решение пользователя 2026-10-06 — вариант «2 + 3 + Ещё…». Прежние решения по раскладке:
docs/decisions/stage5-live-1.md п. 6, 11; stage5-p3-review.md (меню хода — панелью, окно — справочные/выбор модели,
цифра не съедается полем). Соседние партии: COMBAT-PARLEY-PLAN.md (`parley:<target>`), COMBAT-DISARM-PLAN.md
(`disarm`, `pickup`) — их пункты должны лечь в новое меню без отдельной правки UI.

**Задача:** меню хода героя в TUI ≤ 8–10 строк при любом числе врагов: выбранная цель + действия против неё,
короткий блок бесцелевых, свёртки (оружие, оглушающий), всё редкое — в окне «Ещё…».

## 0. Что есть сейчас (факты из кода)
- `combat/available.py::list_options` — плоский список `ActionOption{id, kind, label, params, cost}`,
  отсортирован по `COST_ORDER`. Атаки — декартово «оружие × цель» + дубль «Оглушающая атака» на каждую ближнюю пару
  + особые стрелы × цель; заклинания — × цель; помощь — союзник × враг.
- Цифра → вариант: `game/turn.py::combat_turn` — `text.isdigit()` → `preview_options(...)[n-1].id` (плоский индекс).
  В TUI в бою цифра сейчас НЕ горячая клавиша (`ui/tui/blocks.py::pickable` возвращает `[]`), игрок печатает «3»+Enter.
  `/spells` в бою (`app.py::spell_chosen`) шлёт тот же плоский номер (`row[3]`).
- Рассказчик/классификатор: `combat_flow.option_list` → `[{id,label,cost}]` в промпт `combat_classify`,
  `next_options` в `combat_narrate`. Авто-герой и контроллеры работают по `o.id` (`combat/controllers.py`,
  `game/controllers.py`).
- TUI: блок `turn_menu` (`ui/screen.py::combat_blocks`) → `app.py::show_block` → `format.turn_menu_lines(..., PANEL_WIDTH=54)`
  в `Panel #actions` (Static, не кликабелен, `max-height: 24`). Простой режим: `simple.py::render` → тот же
  `turn_menu_lines` на ширину `ui.width`.

## 1. Главный принцип: движок и протокол не трогаем, меняется только представление
- `list_options`, `ActionOption`, `option_list`, плоская нумерация «цифра+Enter», авто-герой, контроллеры, промпты —
  **без изменений**. Новое меню — слой отображения поверх плоского списка: каждая видимая строка ссылается на
  `option.id`; при выборе TUI находит плоский индекс этого id и шлёт `start_turn(str(index))` — ровно как `/spells`.
- Следствие: рассказчик видит тот же полный список, golden-тесты протокола не меняются, «словами» работает как раньше.
- Единственная правка вне UI (контракт для parley/disarm и будущих): **у целевого варианта цель лежит в
  `params["target"]`** (атака, заклинание, transfer_mark, parley, disarm — уже так/по плану); исключения перечислены
  в `target_of` явно (help → `params["enemy"]`). Без изменения id/лейблов.

## 2. Модель данных — чистые функции, новый модуль `src/ai_dm/ui/combat_menu.py` (без Textual)
Рядом с `ui/format.py`/`ui/screen.py`, тестируется на голых `ActionOption`.

```
MenuRow{key: str, label: str, option_id: str | None, kind: "option"|"expand"|"more"|"target", marks: str}
MenuView{target: str|None, targets: list[TargetChip], target_rows, free_rows, more: list[ActionOption], header: str}
TargetChip{ref, name, hp_text, zone_mark, letter}
```
- `target_of(option) -> str | None` — ref врага-цели (`params["target"]` для kind attack/cast/transfer_mark/parley/disarm,
  `params["enemy"]` для help; для cast — только если target — враг-участник, не зона/союзник/список).
- `targets(options, roster) -> list[TargetChip]` — уникальные цели из вариантов, порядок: своя зона → соседние →
  остальные, внутри — порядок участников. `roster` — лёгкий срез участников (ref, имя, HP-текст, зона), строится
  в `ui/screen.py::combat_blocks` и кладётся в `Block.args` (сейчас там 5 полей — добавить 6-е, `simple.py`
  его игнорирует).
- `default_target(chips, last_target) -> ref` — последняя выбранная игроком цель, если она ещё в списке; иначе первая
  (ближайшая). Память `last_target` — в TUI-приложении на бой (сброс при смене `combat_id`), не в сейве.
- `build_view(options, roster, target, nonlethal, expanded) -> MenuView`:
  - **Блок цели** (по порядку): атаки по цели — одна строка на «основное» оружие (первое из `attacks_of`, т.е. порядок
    движка), остальное оружие + безоружный + импровизированный + особые стрелы → строка «Другое оружие ▸» (kind expand);
    при `nonlethal=True` строка атаки ссылается на `…:nonlethal`, если такой id есть, иначе остаётся обычной с пометкой
    «(дальнобойным — не оглушить)»; дальше переговоры, обезоруживание, заклинания/метка на цель (≤ 2 строки,
    больше → «Заклинания на цель ▸»), «Помочь X против цели» → в «Ещё…».
  - **Бесцелевой блок**: «Идти ▸» (если зон > 1, иначе «Идти: <зона>»), Рывок, Уклонение, Отход, Второе дыхание /
    Проворное бегство, Стабилизировать (если есть — срочно, не прятать), Заклинания без цели ▸, «Закончить ход».
  - **«Ещё…»** (kind more): всё остальное + **полный плоский список** (страховка: любой вариант достижим за 2 нажатия) —
    спрятаться, помощь, предметы/эликсиры, вырваться, бежать, перенос метки на нецелевых, подобрать оружие (disarm),
    варианты по прочим целям.
  - **Лимит:** `MAX_ROWS = 10` (header не считается). Если не влезло — хвост бесцелевого блока по приоритету уезжает
    в «Ещё…» (функция `fit(rows, limit)`), так ≤ 10 гарантировано при любом числе врагов/оружия.
  - **Раскрытие** (`expanded = "weapons" | "move" | "spells_target" | "spells_free" | None`): строки группы заменяют
    блок цели/бесцелевой блок целиком; первая строка «← Назад». Тоже ≤ 10 (больше → прокрутка в панели, кламп не
    нужен: подменю ограничено оружием/зонами).
  - `header` — ресурсы (`resources_line` как сейчас) + «ещё N из 2 атак» вместо суффикса к каждой атаке
    (суффикс в `label` остаётся для LLM; в представлении его срезать — `short_label(option, target)`, убирает « → Имя»,
    т.к. цель уже в заголовке).
- Категории — таблица `CATEGORY_BY_KIND` в этом же модуле; новый kind без записи → по умолчанию в «Ещё…»
  (новые партии не ломают лимит; parley/disarm добавляют одну строку в таблицу — блок цели).
- Пустой случай: врагов-целей нет (все вне досягаемости) → блок цели скрыт, строка «Цель: нет в досягаемости»,
  бесцелевой блок занимает место.

## 3. TUI-взаимодействие (`ui/tui/`)
- **Виджет** `CombatMenu(Vertical)` в `widgets.py` вместо `Panel #actions` в бою (вне боя `#actions` не показывается и
  сейчас): заголовок-ресурсы + `TargetBar` (кликабельные «чипы» целей, как `Choice`) + строки `Choice`
  (переиспользовать класс: номер, клик → сообщение). Строка выше `MAX_ROWS` не рисуется.
- **Клавиши** (только в бою, только при пустом поле ввода — тот же механизм `check_action` +
  `Entry.check_consume_key`, что у меню 2.2):
  - `1..9`, `0` — строка меню (0 = десятая; «Ещё…» всегда последняя строка).
  - Смена цели: `Tab` / `Shift+Tab` по кругу (при пустом поле и без подсказки — сейчас `Tab` там и так уходит в
    `SkipAction`), клик по чипу. Цифры за целями не закрепляем — они заняты действиями.
  - Оглушающий: `F3` (переключатель, состояние в заголовке «Оглушающий: вкл»; сброс после атаки — вопрос В3).
  - «Ещё…»: строка меню или `F4`. `Esc` — из раскрытия назад; в модалке — закрыть без выбора.
  - Буквы — нельзя (первая буква фразы «стреляю…» должна попадать в поле).
- **Ввод «цифра+Enter»** в поле (вставка, привычка): трактовать как номер **видимой** строки (перевод через view),
  чтобы на экране не было двух нумераций. Простой режим и протокол по-прежнему — плоский номер.
- **«Ещё…»** — `MoreModal(ModalScreen)` в `modals.py` по образцу `ModelModal`/`SpellModal`: на весь экран
  (`#modal` 90%), `OptionList` с заголовками групп по `COST_TITLES` и целям, цифры 1–9 + Enter + клик, Esc.
  Результат → `option_id` → плоский индекс → `start_turn`.
- **Эхо в ленту**: полный `label` варианта (с целью), как сейчас `write_echo`.
- **Фокус**: после выбора/Esc фокус в `#input` (как `spell_chosen`/`model_chosen`); пока `busy` — клавиши меню
  отключены (`check_action`).
- **/spells в бою** — без изменений (шлёт плоский номер), но после смены цели в меню не влияет.
- Состояние UI (`target`, `nonlethal`, `expanded`) — поля `TuiApp`, сброс `expanded` после каждого хода,
  `target` — если цель выбыла.

## 4. Рассказчик, протокол, авто-герой
- Промпты `combat_classify`/`combat_narrate` — без изменений (полный плоский `option_list`). Проверить golden.
- `COMBAT_HINT` (`format.py`) — для TUI новый текст: «Tab — сменить цель, F3 — оглушающий, 0/«Ещё…» — остальное;
  можно словами…». Разнести: `COMBAT_HINT` (простой) и `strings.COMBAT_HINT_TUI`.
- Авто-герой/контроллеры/sim_combat — по id, не затронуты. Тест-регрессия: `list_options` выдаёт тот же список (snapshot).

## 5. Ширина узкого режима
- Панель `#side` 58 (`PANEL_WIDTH = 54` текста). Строки меню **не переносятся**, а обрезаются с «…» (`clip(label, width-prefix)`),
  иначе бюджет 10 строк ломается переносами. Чипы целей — в одну-две строки: «[Гоблин 7/7] [Гоблин 2/7] …», при
  нехватке — «Цель: Гоблин (1/4) Tab»; полный список целей — в «Ещё…».
- `< WIDE` (выдвижной `#side`, F2): то же меню; `max-height #actions 24` → для `CombatMenu` `height: auto`,
  карта «Бой» берёт остаток (`1fr`) — проверить на 100×30 и 80×24.

## 6. Простой режим (`ui/simple.py`)
Рекомендация: **не трогать** — плоский нумерованный список (протокол «цифра = плоский номер», словами — как есть),
прокрутка терминала снимает проблему высоты. Альтернатива (вопрос В5): та же группировка текстом — «Цель: Гоблин (сменить:
`цель 2`)», двухшаговый ввод; дороже (команда смены цели в `PlaySession`, правка golden), выигрыш меньше.

- Цели нет в досягаемости → блок цели пуст, «Цель: нет в досягаемости».
- Help: цель = enemy; заклинание на зону/союзника/себя → бесцелевой блок; лечение союзника → «Заклинания ▸».
- `short_label` убирает « → Имя» и «(ещё N из 2)», `header` содержит «ещё N из 2».
- `more` ⊇ все варианты, не показанные строками (каждый id достижим).
- Регрессия: `option_list`/промпт и `list_options` не изменились (snapshot на бою с 3 врагами).

## 9. Риски
- R1 Две нумерации (видимая в TUI и плоская для протокола/простого режима). Меры: TUI всегда переводит через view,
  плоский номер наружу не показывается; тест «3+Enter».
- R2 Tab: сейчас в `Entry` — дополнение команды/смена фокуса; в бою при пустом поле перехватываем. Shift+Tab — проверить,
  что фокус не теряется.
- R3 Preview-движок считается на каждый ход (`preview_screen`); view строится из уже полученных опций — лишних
  вызовов движка нет. Не вызывать `preview_options` повторно для перевода номера — брать из того же блока.
- R4 Расхождение view ↔ плоский список, если опции пересчитались между отрисовкой и выбором: искать по id в свежем
  `preview_options`, не по сохранённому индексу; id пропал → note «вариант больше недоступен».
- R5 Мульти-шаговый ход (после шага меню «что осталось»): цель сохраняется между шагами хода.
- R6 Конфликт файлов с parley/disarm: они правят `available.py`/контроллеры, мы — `ui/`; общая точка — только
  `CATEGORY_BY_KIND`. Порядок: эта партия после parley или параллельно, disarm — после (его `pickup` сразу в «Ещё…»).
- R7 Атаки «по основному оружию» — порядок из `attacks_of`; если герой сменил оружие в руках (disarm), основное
  меняется — ок, берётся текущий порядок.

## Ответы проектировщика (2026-10-06)
В1–В6 — по рекомендациям (Tab + клик по строке целей; «Ещё…» — полный список; оглушающий держится до выключения; «Ещё…» —
строка меню + F4; простой режим не трогать; цифра+Enter — номер видимой строки).

(лишнее — в «Ещё…»), но оружие вытесняется последним.
