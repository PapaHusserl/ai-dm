# Часть A. Архитектура этапа

- `ui` остаётся верхним слоем; сторож `tests/unit/test_architecture.py` не меняется по сути. Добавить сторож: **`textual` импортируют только
  `ai_dm.ui.tui*`** (и `ui.cli` — лениво, внутри функции запуска), чтобы простой режим и все нижние слои жили без Textual.
- Новые модули: `ui/screen.py`, `ui/session.py`, `ui/tui/__init__.py`, `ui/tui/app.py` (App + раскладка), `ui/tui/widgets.py`

## A2. Модель экрана `ui/screen.py` [Т3]
Чистые функции без ввода-вывода, общие для двух режимов: из `GameApp` + `Reply` строят список **блоков**:
`Block(kind, text | items, title?)`, где `kind ∈ {narration, roll, note, boundary, raw, hint, menu, combat_map, turn_menu, combat_hint,
status, gains}`. Сюда переезжает логика из `simple.py`: `status_line`, порядок вывода `show_reply` (фильтр `SERVICE_PREFIXES`, броски vs
заметки, рамка рассказа, строки границы, итог боя), выбор экрана `show_screen` (pending-меню / меню боя / варианты), `LABELS`, `limit_state`.
- Простой режим: `simple.render(block, width) -> list[str]` через существующие `format.*` — **байт-в-байт тот же вывод**.
- TUI: каждый `kind` направляется в свой виджет (рассказ → лента, `roll` → лог бросков и лента, `combat_map`/`turn_menu` → панель «Бой»,
  `menu` → блок вариантов под лентой, `status` → строка состояния, `gains` → «Получено»).
- Блок `gains` («Получено», V2): опыт за победу — уже есть (`xp_before`); предметы/золото/трофеи — из разницы инвентаря/кошелька героя до и
  после хода (снимок в контроллере). В простом режиме `gains` печатается **только** строкой «Получено опыта: N», как сейчас (не менять вывод);
  полный раздел — в TUI (вопрос Q4).

## A3. Контроллер ввода `ui/session.py`
Сейчас цикл `simple.run` держит состояние, которого нет в `GameApp`: меню мягкого лимита (`warned/asked/limit_menu`), разбор цифры
(pending-меню / варианты вне боя), автосейв при конце ввода, отказ сохранять при смерти, `opening`, перехват исключений с `redact`.
Выносим в класс `PlaySession(app, replay, secrets, opening)` с методом `submit(line) -> Step` (блоки для вывода + флаги `quit`/`exit_code`/
`busy`) и `start() -> Step`, `finish() -> Step` (EOF/выход). `simple.run` превращается в тонкий цикл «read → submit → render».
TUI вызывает тот же `submit` в worker'е. Так меню 2.2, лимит, смерть, уровень и /model ведут себя одинаково в обоих режимах.

## A4. Старт [Т4, уточнено]
`ask_hero` уже читает через `stdin.read` (это `InputSource`), но печатает в `stdout` до создания `GameApp`; `pick_narrator`, сообщения
`merge_pack`, «Мир: …», путь replay — тоже `say(stdout, …)`. Решение: **подготовка мира (`play` до `GameApp`) остаётся в простом построчном
виде и выполняется до запуска Textual**, но все строки старта собираются в `startup` (список) и в TUI показываются первыми блоками ленты;
выбор героя в TUI-режиме — экран выбора внутри TUI (модалка-меню) через абстракцию `HeroPicker` (простая реализация = нынешний `ask_hero`).
Иначе пришлось бы переносить в TUI всю `play` — лишняя связность. Вступление (`OPENING`) — первый `submit` в worker'е, как сейчас.

## A5. Ход в worker'е [Т2]
`GameApp` синхронный → `run_worker(thread=True, exclusive=True)`; пока ход идёт: поле ввода `disabled`, в строке состояния «Мастер думает…»
(индикатор), результат возвращается через `call_from_thread`. Ошибка хода → блок `note` с `redact`, как в простом режиме. Ctrl+C / выход во
время хода — дождаться конца хода (ход атомарен, 2.3), затем автосейв; второй Ctrl+C — выход без сейва (как `KeyboardInterrupt` сейчас).

## A6. Выбор режима и fallback (В2 а)
`cli.make_parser`: `--simple` (флаг). Режим TUI, если: нет `--simple`, `stdin` и `stdout` — tty, `TERM != "dumb"`, ввод/вывод не
подменён тестом (`main(stdin=…)` → простой), и `import ai_dm.ui.tui` удался. Иначе простой. Ошибка старта TUI (исключение до первого
кадра) → сообщение «TUI не запустился: <причина>, простой режим.» (с `redact`) и продолжение в простом режиме **с тем же `GameApp`**
без трейсбека. `--replay` и `--mock` работают в обоих режимах.

## A7. Только русский
Все свои строки — в `ui/tui/strings.py`. Встроенные английские строки Textual: отключить палитру команд (`ENABLE_COMMAND_PALETTE = False`),
свои `BINDINGS` с русскими `description`, Footer — только с нашими привязками, без встроенных (`ctrl+q` «Выход» переопределить), заголовок/
подзаголовок — свои, `notify` — свои тексты, `Input.placeholder` — свой. Тест-сторож: обход всех видимых виджетов и Footer после
старта/хода/модалки — нет латиницы в видимом тексте, кроме белого списка (идентификаторы моделей `provider:model`, `id` мира, «HP», «КД»?,
`$`). Белый список — в тесте.

## A8. Раскладка (В3, предварительно)
Ширина ≥ 120 колонок: слева (≈ 80) — лента сцены (прокрутка, ход ниже предыдущего, V-«лента»), под ней блок вариантов/меню, внизу поле ввода и
строка состояния на всю ширину. Справа (≈ 38–48, V1) сверху вниз: место под рисунок (скрыто, пока рисунка нет — В7), краткий лист героя
(HP, КД, ячейки, состояния, концентрация), «Бой» (карта зон + меню действий, только в бою; занимает верх правой колонки), «Броски» (лог),
«Получено» (последний ход; пусто — скрыто). < 120 колонок — одна колонка, правая панель открывается клавишей (F2) поверх. Цвет — Q3.

## A9. Модалки и выбор (В4, /model, меню 2.2)
- `/sheet /inv /spells /abilities /cost` → модальный экран с текстом ответа команды (те же строки `Reply.lines`/`raw`), закрытие Esc.
  Распознаётся в TUI по имени команды до отправки, ответ берётся из того же `PlaySession.submit` (без дубля логики `game.commands`).
- `/help`, `/save`, `/load`, `/tone`, `/report`, `/retire`, `/map`, `/quit` — в ленту.
- Pending-меню (`error_menu` 2.2, `model_choice`, `level_up`, `hero_dead`, `tone_confirm`) и меню лимита — блок вариантов под лентой
  (не модалка: игрок должен видеть рассказ), выбор цифрой или кликом (В9) → отправляется цифра в `submit`. «Сменить модель» из 2.2 →
  `model_choice` — тот же список. `/model` без аргумента — в ленту (как сейчас), смена — `/model narrator провайдер:модель`.

# Часть D. Риски
1. **Байт-в-байт при выносе в `screen`/`session`** — много мелких веток вывода; P0 нельзя сливать с правкой ожиданий. Делать
   механически, сперва `session`, потом `screen`.
2. **Потоки:** `GameApp` из worker'а, а Pilot читает состояние из главного потока — читать `app.bundle` только после завершения worker'а;
   доступ к `GameApp` — только через `PlaySession` и только из одного worker'а (`exclusive=True`).
3. **Медленные и хрупкие Pilot-тесты** (тайминги) — ждать `pilot.pause()`/`workers.wait_for_complete()`, без `sleep`; фиксированный `size`.
4. **Встроенные английские строки Textual** могут появиться с обновлением версии — сторож A7 + верхняя граница версии в `pyproject` (вопрос:
   пиннинг `textual>=X,<X+1`).
5. **Ширина кириллицы/псевдографики** в Textual корректна (Rich cell width), но рамки `format.frame_lines` в ленте TUI не нужны — в TUI
   рассказ рендерится без псевдо-рамок (рамки дают виджеты); иначе двойные рамки.
6. **Ctrl+C внутри Textual** — перехватывается App, а не `KeyboardInterrupt` в `main`; поведение «атомарный ход + автосейв» реализовать явно.
7. **`uv tool install`** — `textual` тянет `rich`, `markdown-it-py` и др.; проверить размер/время установки, конфликтов с `anthropic`/`google-genai` нет
   (проверка в P1).
8. **Windows** не обещаем, но не ломаем: никаких `termios`/`fcntl` в нашем коде, только API Textual.
