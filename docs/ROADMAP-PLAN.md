## 0. Факты из кода, меняющие объём (важно до утверждения)

1. **Трек 1.5 не закрыт для 4 из 5 классов.** В `srd/data/classes/` у воина, плута, жреца и волшебника умения есть
   только для 1-го уровня (у плута — только `weapon_mastery`; Скрытой атаки, Канала божественности, Магического
   восстановления нет вообще). Полностью на 1–5 сделан только следопыт (Охотник и Повелитель зверей). SRD-подклассов
   Чемпиона, Вора, Домена жизни и Воплощения в `srd/data/subclasses/` нет. Монстров SRD — 3 (гоблин, босс гоблинов,
   стражник; по ТЗ 6 их должно быть 20–30). Заклинаний — 17. Значит, в п. 1 бэклога неверно сказано, что «умения
   классов есть до 5». Сначала нужно доделать 1–5 для всех классов, и только потом поднимать уровни.
2. `MAX_LEVEL = 5` — константа в `rules/progression.py:15`, её импортирует `rules/xp.py`. Таблицы `xp` и `proficiency`
   есть до 20, а `spell_slots_full`/`spell_slots_half` — только до 5.
3. Ресурсы существа — универсальный `CreatureState.resources: dict[str, ResourcePool]` (`state/creature.py:53`).
   Ярость, ки, очки чародейства и ячейки договора колдуна ложатся в него **без миграции**. У героя
   `feature_options: dict[str, str]`: это один вариант на умение. Для множественных выборов (воззвания колдуна,
   метамагия) понадобится новое поле.
4. `persistence/store.write_slot` пишет во временный каталог и делает `os.replace`, но `fsync` нет (п. 3 актуален).
5. `persistence/migrations`: `CURRENT_SCHEMA_VERSION = 7`, миграции m0001…m0007, `MigrationContext` (пак до сейва)
   уже есть — новые миграции делаются по образцу m0006/m0007.
6. У героя уже есть `motive/means/opportunity`, `afterlife`, `legacy_links`, статусы `in_afterlife/ascended/retired`.
   Для 6б миграция не нужна; для этапов 8–9 часть полей уже заложена.
7. `tables/lifespan.yaml` уже содержит человека, полурослика, дварфа и эльфа: хвост п. 9 «старость прочих видов» закрыт.
8. В `devtools/sim_combat.py` есть симулятор боя — опора для калибровки сложности (п. 6) без живых вызовов.

### Почему такой порядок (решение 6; в R4 дополнено, см. roadmap-r4-unified.md)
- **К0+К1 сразу после 6б:** движок и ядро заклинаний чинят живого следопыта (апкаст, концентрация, `cast_spell` вне
  боя) и вводят всю схему v9, так что дальнейшие классы — без миграций.
- **К7 раньше новых классов:** монстры и сложность (п. 6) нужны живой игре уже сейчас; баланс калибруется на 5
  готовых+частично готовых классах, затем перепроверяется прогоном sim_combat в каждой партии К2–К6 (дешёво, без LLM).
- **Ж0–Ж3 раньше К2–К6:** ценность для живого мира выше; Ж0 не задевает схему классов (v9 уже полная), К2–К6 не
  задевают схему Ж (проверено по составу полей, раздел 3).
- **Ж4–Ж7 после К2–К6:** Ж4 опирается на таблицу ПО из К7 (уже есть), напарники (Ж5–Ж7) выигрывают от полного набора
  классов (напарник-жрец/воин); зверь следопыта — без изменений.
- В 6б выбор класса — из реестра: новые классы К2–К6 появятся в создании героя автоматически.

### Уровни: движок до 20 в К0, контент ступенями (решение 1)
- К0: `MAX_LEVEL` → потолок контента из реестра (наименьший уровень, до которого у всех классов есть умения и
  таблицы); таблицы ячеек, ячейки договора, ПХ/черта 4/8/12/16/19, бюджет боя и урон по тяжести — на 1–20.
- Ступень I (1–5, все 12 классов) — К2–К7 в этом плане. Ступени II (6–10) и III (11–20) — **отложены** (заменено R4: в очереди #30–32 и #51–54): груминг
  ступени II стартует, когда живой герой выйдет на 5 ур. (сейчас Грей 3-го). Потолок не ломает героя: `can_level_up` молчит.
