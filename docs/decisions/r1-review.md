## Замечания
1. (низкая) `fold_text` вызывает `defeated_text`/`losses_text`/`trophies_text` по два раза (проверка `and` +
   подстановка). Посчитать в локальные переменные один раз — или вынести в хелпер `part(label, text)`.
   Это же — кандидат на снижение smells (см. п. 4).
2. (низкая) `participant_name(state, {hero.id: hero}, p.ref)` повторён трижды в combat_fold.py. Можно собрать
   `heroes = {hero.id: hero}` один раз либо сделать `name_of(state, hero, ref)`. Не обязательно.
3. (средняя, вопрос проектировщику) losses_text: «ранен» = `hp_current < hp_max`, а не «есть HP-строка героя в
   логе» (план п. 2.4). Решение Q2а дословно — «HP героя к концу боя, если ранен», так что реализация ему
   соответствует, а план п. 2.4 детализировал строже. Расхождение: герой, вошедший в бой уже раненым и не
   получивший урона, получит «потери: <герой> HP a/b» — в сводке боя это ложная потеря. Обратный случай (урон
   получен и вылечен до max) — потери не будет, это приемлемо. Лог-вариант ловит первый случай, но тянет разбор
   строк («: HP» с именем героя, «Царапина» без имени), т.е. регулярки, от которых Q2а уводил.
   **Рекомендация:** оставить по состоянию (просто, детерминировано, соответствует Q2а), поправить формулировку
   п. 2.4 плана/BACKLOG постфактум. Если проектировщик хочет точности — дешёвый путь не лог, а сравнение с HP
   героя на старте, но поля для этого нет (сейв v9 без полей) — значит отдельная задача.
   Мелочь: при гибели героя выйдет «герой погиб … потери: <герой> HP 0/N» — дубль смысла, но не ошибка.
4. (средняя) smells 206/206 — запас ноль, следующая партия упрётся. Что можно снять в Р1 без смены поведения:
   - п. 1 (двойные вызовы в `fold_text`) — длинное выражение с `and`-цепочкой, вероятный источник smell;
   - в `participant_name` словарь `{p.ref: p.name ...}[ref]` строится на каждый вызов — `next(p.name for p in
     state.participants if p.ref == ref)` проще (не smell, но заодно);
   - `defeated_text`: локальная перепись `status` при ended_by_master — можно `status = "surrendered" if ... else
     p.status` одной строкой.
   Точного списка smells по новым файлам qlty без пути не дал — kaban'у проверить `qlty smells --all` по
   combat_fold.py до/после. Поднимать SMELLS_MAX — не в Р1, вопрос проектировщику только если не удастся снять.
5. (инфо) Флак `tests/unit/ui/tui/test_tui_turn.py::test_second_ctrl_c_calls_hard_exit_with_130_and_does_not_save`
   с Р1 **не связан**: на чистом HEAD (3ae371f, отдельный worktree) падает 4/4 с
   `[(130, [], 1)] == [(130, [], 0)]` — поток хода успевает применить ход до `hard_exit` (гонка гейта в тесте/TUI).
   С Р1-диффом — 1 pass из 5. Р1 трогает только боевой путь turn.py, тест идёт ходом исследования без боя.
   Завести в BACKLOG отдельным пунктом.
