## Суть
TZ 10: TUI на Textual — панель сцены, лист персонажа, лог бросков, поле ввода; строка состояния со стоимостью сессии (2.0);
`/cost` — разбивка по ролям/моделям за сессию/день/мир. Простой построчный режим остаётся как fallback и не ломается.
Критерий «все панели и команды работают» сейчас не проверяем тестом — его надо перевести в проверяемый (см. черновик, P5).

## Что уже есть
- Простой режим целиком: ui/simple.py (`run`, меню, бой, строка состояния, мягкий лимит), ui/format.py (перенос по
  `ui.width = 80`), ui/io.py (`InputSource`/`OutputSink`, `ScriptedInput`/`CaptureOutput` для тестов).
- `GameApp` синхронный, без ввода-вывода, отдаёт `Reply(lines, raw, narration, turn, pending, menu, hint, quit)` — TUI может
  жить поверх него без правки game.
- Команды (game/commands.py): /help /save /load /model /cost /sheet /inv /spells /abilities /map /quit /tone — работают;
  /report — заглушка «этап 6», /retire — заглушка «этап 9».
- Строка состояния: HP, КД, дата/время, «сессия $X» (simple.status_line).
- /cost: сессия/день/мир, отдельно список по ролям и отдельно по моделям (CostLedger, meta/costs.jsonl).
- Мягкий лимит 2.0: есть, выключен по умолчанию, меню «продолжить / сохранить и выйти».

## Чего нет
- Textual нет в зависимостях (pyproject: anthropic, google-genai, pydantic, pyyaml).
- Нет выбора режима в CLI (флага/автоопределения), нет fallback-логики.
- Выбор героя (cli.ask_hero) и вступление (OPENING) идут через stdin/stdout мимо `InputSource` — в TUI не попадут как есть.
- Нет тестов TUI.

## Точки входа, которые TUI обязан покрыть (все, не только ход)
1. Старт: выбор героя (`ask_hero`), выбор нарратора (`pick_narrator` пишет в stdout), вступительная сцена.
2. Обычный ход: рассказ, броски, варианты `offer_choices`, свободный ввод.
3. Бой: меню действий, карта зон (`/map`, `combat_map_lines`), подсказка COMBAT_HINT, ход врагов.
4. Меню сбоя 2.2 (повторить / сменить модель / сохранить и выйти), отказ модели, сбой summarizer (Д2 этапа 4).
5. Мягкий лимит (80% предупреждение, 100% пауза).
6. Повышение уровня с выборами (pending-меню).
7. Смерть героя (`pending == "hero_dead"`).
8. Все команды из HELP, включая заглушки.
9. Режимы `--mock` и `--replay` (replay печатает путь временного каталога).
10. Ожидание ответа модели: до десятков секунд с повторами 1→3→10 с — интерфейс не должен замерзать.

## Технические решения (мини-влад, 2026-10-05; техника, не продукт)
- Т1. game не трогаем: TUI — новый модуль в ui (например, ui/tui.py), работает поверх `GameApp`/`Reply`. Слой ui остаётся
  верхним, тест-сторож архитектуры не меняется.
- Т2. Вызовы `GameApp` в TUI — в рабочем потоке Textual (worker), интерфейс показывает «мастер думает…». Причина: game
  синхронный, ход с повторами длится десятки секунд.
- Т3. Общая «модель экрана» (что показать после Reply: ленту, меню, броски, статус) выносится из simple.py и используется
  обоими режимами — чтобы не разъехались. Простой режим после выноса даёт байт-в-байт тот же вывод (существующие тесты).
- Т4. Выбор героя, выбор нарратора и вступление переводятся на `InputSource`/`OutputSink`, чтобы TUI их показывал.
- Т5. Тесты TUI — headless через `App.run_test()`/Pilot Textual, без живых вызовов, на мок-адаптере.

   worker для хода (Т2); узкий терминал. Готово: Pilot-тест — ход на моке обновляет все панели; ввод заблокирован, пока

P3. Меню и режимы: варианты, бой (меню + карта зон), меню 2.2, мягкий лимит, повышение уровня, смерть героя, модалки по В4,

P5. Приёмка: сценарий «разговор → проверка → бой» этапа 2 проходит на моке и в TUI (Pilot), и в простом режиме

(P4); сценарий этапа 2 зелёный в обоих режимах (P5); существующие тесты простого режима не правились.
Риски: Textual-тесты медленные — следить за временем `pytest`; мутационное тестирование для UI — договориться о пороге в плане.
Вне этапа: BACKLOG 15 целиком; ASCII-контент (если В7 = позже).
