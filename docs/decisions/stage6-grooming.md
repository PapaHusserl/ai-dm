## Вердикт
Не готов до ответов на В1–В6. Этап — пять разных задач под одной строкой. Критерий проверяет только две (репорт и
воспроизведение). Для import, героя на лету и предыстории критерия нет. Сразу можно делать P0: сбор меток хода в репорт-файл
и сам формат файла. От ответов это не зависит, кроме В2 (содержимое) — берём минимум из ТЗ 9.

## Суть
1. Репорты (ТЗ 9): `/report <текст>` и авто-метки `missing-mechanic`, `limit-exceeded`, `invalid-death`, `refusal` →
   markdown в `issues/`: текст, последние N ходов, снимок состояния, сид и состояние RNG, модель, сырой запрос/ответ. Без ключей.
2. Воспроизведение (ТЗ 11): сид + ответы из журнала → точный повтор хода. Репорт несёт нужный фрагмент журнала.
3. `import` (ТЗ 3): текстовая выжимка → ИИ раскладывает по файлам пака → пользователь правит руками.
4. Герой на лету (ТЗ 5, 5.2): описание словами → ИИ предлагает лист → движок валидирует → игрок подтверждает/правит;
   альтернативно пошаговый классический режим; мотив/средства/возможности героя.
5. Свободная предыстория (ТЗ 6): описание словами → ИИ раскладывает по структуре 5.2 → валидатор (3 характеристики,
   2 навыка, инструмент, черта происхождения, снаряжение+золото ≤ 50 зм); 4 SRD — примеры для модели.
Критерий ТЗ 13: «/report и авто-метки создают файл; ход из репорта воспроизводится по сиду + журналу с идентичным состоянием».

## Что уже есть
- Метки авто-репортов в протоколе: `Decision.report_tag`; ставятся `limit-exceeded` (world, combat, resources),
  `invalid-death` (world), `missing-mechanic` (unsupported_action, импровизация в бою), плюс внеТЗшная `invalid-defeat`
  (combat/defeat.py). Собираются в `ctx.marks` / `TurnResult.report_tags` (game/turn.py) и пишутся в журнал (`report_tags`).
- Отказ модели распознаётся (`stop_reason="refusal"` у обоих адаптеров), ход откатывается, игрок видит REFUSAL_HINT.
- Журнал вызовов: `saves/<world>/journal/calls-NNN.jsonl`, блобы по sha256, ротация + gzip, лимит `max_mb`, без ключей,
  `turn_status committed|aborted`.
- Replay: `ReplayAdapter` с отпечатком запроса и `ReplayDivergence`; `ai-dm --replay` требует `--world --seed --hero`, играет
  во временном каталоге — только **с начала мира**.
- RNG с сидом и состоянием в сейве; атомарность хода (копия бандла).
- `/report` — заглушка «этап 6» в обоих режимах (commands.py:273).
- Билдер: `build_character` + `validate_background` (структура 5.2, бюджет 50 зм = 5000 мм, варианты equipment/gold),
  4 SRD-предыстории данными, стандартный набор / покупка очков / явные значения.
- Выбор героя — только пресеты пака (`ask_hero`), `--hero`.

## Чего нет
- Модуля `reports` (ARCHITECTURE его заявляет), каталога `issues/`, записи файла репорта.
- Метки `refusal` в `report_tags`: отказ идёт как сбой хода, метки нет.
- Метка `context_overflow` (ARCHITECTURE C4/память) объявлена в архитектуре, но в коде не найдена grep'ом. Гипотеза:
  ставится иначе или не реализована — проверить разработчику.
- Воспроизведения **одного хода** с середины: нужен снимок состояния до хода + фрагмент журнала этого хода + входная фраза.
  Сейчас replay только с создания мира.
- `import` — ни команды, ни роли модели, ни записи пака.
- Создания героя на лету — ни ИИ-пути, ни пошагового режима, ни хранения мотива/средств/возможностей героя.
- Роли/промпта модели для свободной предыстории; формат «предложение ИИ → валидация → правка игроком».

## Точки входа (все, не только /report)
Репорты:
1. `/report <текст>` в простом режиме и в TUI.
2. Авто-метка в обычном ходе (протокол мастера).
3. Авто-метка в бою (combat handlers, ход без вызова модели — номер действия).
4. Авто-метка `refusal` — на **откатанном** ходе (состояние не применено).
5. Метки вне хода: граница сцены (world, summarizer), ход мира, `context_overflow`.
6. Метки в replay/mock: писать ли файл.
Персонаж:
7. Новый мир с паком без `character.yaml`.
8. Новый мир с паком, где пресеты есть (выбор: пресет или на лету).
9. Продолжить мир (ТЗ 5.2: только на лету) — механики этапа 9 нет.
10. `--hero` из CLI и replay с героем на лету (`--hero` сейчас — id пресета).
11. TUI (HeroPickerApp) и простой режим.
Import:
12. Отдельная CLI-команда вне игры или служебная команда в игре — ТЗ не говорит.

## Противоречия и дыры
1. Критерий покрывает 2 из 5 подзадач. Для import, героя на лету и предыстории проверяемого критерия нет. → В1.
2. «Ход из репорта воспроизводится» vs текущий replay «только с начала мира». Нужен снимок до хода; ТЗ 9 говорит «снимок
   состояния», но не уточняет — до хода или после. → В3.
3. Отказ (`refusal`) — ход откатан. Что воспроизводить: откатанный ход до отказа. Это возможно только если снимок — до хода. → В3.
4. «Последние N ходов» — N не задан. «Сырой запрос/ответ» — один последний вызов или все вызовы хода (рассказчик + world +
   повторы). Блобы журнала — копировать в репорт или ссылаться. → В2.
5. Журнал ротируется и сжимается. Если репорт ссылается на журнал, а не копирует, через время он невоспроизводим. → В2.
6. Авто-метки: файл на каждую метку? `limit-exceeded` может быть частым — десятки файлов за сессию. → В4.
7. `invalid-defeat` и `context_overflow` — метки вне списка ТЗ 9. Писать файл или нет. → В4.
8. Живые миры пользователя: `issues/` внутри `saves/<world>/` или в корне игры — ТЗ пишет «в `issues/`». Снимок состояния
   содержит сюжет игрока — приватность при «позже GitHub Issues». → В5 (не блокирует сейчас).
9. Герой на лету: «ИИ предлагает лист» — какая роль/модель, стоимость, что при отказе/невалидном ответе (2.2 применим?). ТЗ 5:
   «мотив / средства / возможности героя» — в схеме героя есть? Если нет — это изменение данных (новые поля, миграция). → В6.
10. ТЗ 5.2 «продолжить мир — только на лету» требует этапа 9. В этап 6 не входит, явно отмечаю.
11. import: «по файлам пака» — какой состав (все 8 файлов или world/npcs/locations), куда пишется (новый `campaigns/<id>/`),
    валидация 5.3 после правки руками — та же загрузка пака. BACKLOG 2 ждёт import для существ — тогда и `monsters`. → В7.
12. Пошаговый классический режим — объём сравним с ИИ-путём (класс, вид, характеристики 3 способами, предыстория, навыки,
    мастерства, заклинания). Нужен ли он в этапе 6. → В6.
13. BACKLOG 1 «до этапа 6» (уровни выше 5) — связь только тематическая; уровни 1–5 закрыты, на этап 6 не влияет. Не берём.
14. BACKLOG 20 (живые NPC) упоминает «этап 6 (персонажи на лету)» — это про NPC, не про героя. Не берём, отмечаю.
15. Сейв: если репорт/герой на лету добавляют поля в состояние — новая версия схемы (v8) с миграцией (правило 5.3). Изменение
    данных — отдельный объём.

## Технические решения (мини-влад, 2026-10-07; техника, не продукт)
- Т1. Новый модуль `reports` (как в ARCHITECTURE), слой не выше game; запись файла — после хода (commit или abort), из game.
- Т2. Метка `refusal` добавляется в `report_tags` сбоя хода (turn.py), отдельно от протокола.
- Т3. Ключи: репорт собирается только из бандла и журнала (там ключей нет по C4); тест-сторож — в файле нет значений
  переменных `*_API_KEY`.
- Т4. Детерминизм проверяется сравнением сериализованного бандла после хода (как в тесте сейв → загрузка этапа 1).
