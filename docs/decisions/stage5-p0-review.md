## Хорошо
- Перенос из `simple.py` построчно эквивалентен старому циклу: порядок вывода хода, `raw` только при непустом, автосейв при EOF
  (не в replay, не при смерти), меню лимита, «Нет такого варианта», цифра в бою, `redact`, replay → 1. Логика в `simple.py` не
  задублирована: там остались только `render` и цикл «read → submit → render».
- `submit` синхронный, возвращает `Step`, сам ничего не печатает — для TUI годится: вызвать в worker-потоке, блоки отдать через
  `call_from_thread`.
- Тест-сторож на импорт `textual` по AST; тесты блоков проверяют `kind` и порядок, а не текст рамок.

## Отступления от плана
- HeroPicker и сбор строк старта в `cli.py` перенесены в P1–P3 — допустимо: старт героя не нужен для `PlaySession`, P0 закрывает
  контроллер игры. Нужно записать перенос в план (сейчас P0 в плане их перечисляет).
- `Step.busy` не введён — допустимо: признак «ход идёт» принадлежит TUI (worker), не сессии; в P0-приёмке его нет.
- `take_opening()` без тестов — допустимо условно: три строки, покрыт сценариями через `simple.run`. Но TUI будет вызывать его
  напрямую — желательно один юнит-тест (отдаёт opening один раз, потом None; `start()` при opening не показывает прошлый рассказ).

   «Опыт: +N» (из `gains_lines`). Предложение: в `gains_lines` не писать опыт, если победа (или в TUI показывать только `items`,

   комментария в коде/ARCHITECTURE F2: «вызывать один раз на ход, перерисовку делать из сохранённых блоков».
3. Тест на `take_opening` (см. выше).
