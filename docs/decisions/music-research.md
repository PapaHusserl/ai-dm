# Исследование: тематическая музыка/эмбиент по ситуации (дядя-кабан, 2026-10-08)

**Идея:** проигрывать в терминальной игре музыку/эмбиент по ситуации (бой, таверна, романтика, исследование), выбирая трек из сигналов движка, без лишних вызовов LLM.

Пометка «(по памяти, не проверено)» — утверждение не подтверждено поиском в этой сессии.

Генерация в рантайме отпадает: нужна GPU/сеть, задержка, вес моделей. Разумно только **офлайн-сгенерировать один раз** набор лупов (Stable Audio) — но качество лупа и шов надо проверять руками. Проще и честнее — курируемый набор CC0/CC-BY (8–15 треков) + файл ATTRIBUTION.

Рекомендованная схема: игра поставляется без музыки или с маленьким CC0/CC-BY паком; пользователь может указать свою папку (в т.ч. скачанный им Tabletop Audio для личной игры — это его некоммерческое использование).

## 3. Воспроизведение из Python (терминал, macOS+Linux)

| Вариант | Плюсы | Минусы |
|---|---|---|
| miniaudio (pyminiaudio) | Колёса на PyPI, нет системных зависимостей, mp3/flac/ogg/wav, стриминг через генератор — кроссфейд и громкость делаются в своём генераторе смешиванием сэмплов | Кроссфейд/микширование писать самим (~100–150 строк) | https://github.com/irmen/pyminiaudio |
| pygame.mixer | Есть fadeout/громкость/каналы из коробки (по памяти) | Тянет весь pygame (~десятки МБ), инициализация SDL, шум в stdout | — |
| mpv через JSON IPC (python-mpv-jsonipc) | Любые форматы, громкость/пауза через IPC, отдельный процесс не мешает Textual | Требует установленный mpv (brew/apt) — внешняя зависимость; кроссфейд — двумя инстансами + плавная громкость | https://pypi.org/project/python-mpv-jsonipc |
| python-vlc | Мощно | Нужен установленный VLC, тяжело | — |
| simpleaudio | Просто | Только WAV, проект заброшен (по памяти, не проверено) | — |
| sounddevice | PortAudio, гибко | Декодирование отдельно (soundfile), PortAudio на Linux системный | — |

Рекомендация: **miniaudio как опциональная зависимость** (`pip install ai-dm[audio]`), при отсутствии — тихий no-op. Аудио в отдельном потоке, наружу — интерфейс «поставь тему X / громкость / mute». Кроссфейд 1.5–3 с.

## 4. Привязка к движку (без LLM)

Сигналы, которые уже есть (docs/ARCHITECTURE.md): `SessionState.active_combat` и события `combat_ended`, `location_visited`; `Location.tags`; `World.tone`; `current_scene`. Схема — как у Foundry-модулей:
- приоритеты: бой > сцена-событие > локация > тон мира > тишина;
- маппинг `tag → тема` в TOML/YAML (таверна → `tavern`, лес → `forest`, подземелье → `dungeon`);
- «романтика/ужас» — если у сцены уже есть тон/теги от мастера (протокол), брать оттуда; нового вызова LLM не нужно. Если тона сцены нет — максимум добавить необязательное поле `mood` в уже существующий ответ мастера (0 доп. вызовов).
- гистерезис: не менять трек чаще раза в N секунд, после боя — вернуть прежнюю тему.

## Строительные блоки
pyminiaudio; (альтернатива) mpv + python-mpv-jsonipc; CC0/CC-BY треки с Incompetech/OpenGameArt/freesound; опционально офлайн Stable Audio.

## Свободная ниша
Адаптивная музыка в терминальном AI-DM — никто из найденных не делает. Готового Python-компонента «контекст → трек с кроссфейдом» не найдено.

## Вердикт
**Собрать из готовых кусков, но не сейчас (после ядра/AD1).** Это фича «приятности», не влияющая на геймплей; риск — лицензии и подбор треков, а не код.

Оценка: MVP (miniaudio, 5–6 тем, бой/локация/тон, кроссфейд, громкость/mute в настройках и команде, no-op без зависимости, тесты маппинга) — ~1 партия, 2–4 дня. Подбор и проверка лицензий треков — отдельно 0.5–1 день. Настроение сцены от мастера (`mood`) — +0.5 дня. Генерация треков — не делать.
