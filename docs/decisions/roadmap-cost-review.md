# Проверка ROADMAP-PLAN кабаном-тестем (2026-10-08) — ждёт решений проектировщика

Вердикт: план эффективен с правками. Оценка 16–18 млн реалистична, честно 18–21 млн (svekrov, kvoliti, круги переделок;
медиана прошлой партии ~365 тыс., L-партия 520–630 тыс.).

Предложения (экономия):
1. Ступени II/III блока К (К8–К14, ~3 млн) отложить, пока живой герой не подойдёт к 5 ур.; движок до 20 — в К0.
2. Контент К (YAML): генерация скриптом из SRD 5.2 (CC-BY) или дешёвой моделью + облегчённый конвейер (загрузка,
   test_classes_build, выборочные бои, mama-kaban) без doeba/mutmut; полный — только для кода обработчиков (~1 млн).
3. Слить: A1+D1, Ж8 (бюджет памяти) → Ж0, Н4+Н5, П0 → М0/Б (~1–1,3 млн).
4. kaban-doeba (45–55% партии): на вход — только diff и список функций; разбор мутантов — меньшей моделью (~2–2,5 млн, не проверено).
5. Миграции «нейтральные по поведению» — снимают паузы живой игры.
6. Порядок по ценности: A+D → 6б → К0+К1 → К7 (монстры и баланс) → Ж0–Ж3 → новые классы К2–К6 → М/П/С/Н.
7. Цена хода: в промпт — только класс героя и подготовленные заклинания; бюджет памяти NPC; стабильный кэшируемый
   префикс; порог ≤ ~$0.03 за ход (+35%), иначе ревизия контекста; cache_write/read замерять на прогонах.
Итог при правках: ~11–13 млн, 33–36 партий вместо 42–47.
