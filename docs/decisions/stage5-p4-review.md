  `test_by_role_model_cells_sum_to_total_to_the_nano` на нечётных значениях (7, 3_000_000_001) проверяет равенство для сессии/дня/мира.
- DataTable строится из `cost_rows(report)` (кортежи с нано-int), а не парсингом строк; `Reply` не тронут — выбран предпочтительный

- Тест окна сверяет каждую ячейку DataTable с `cost_rows` + заголовки, и требует непустую строку `narrator` — тест не пустой.

- `test_every_help_command_is_covered`: `sorted(COMMANDS) == sorted(HELP)` — обработчик без строки в HELP (и наоборот) роняет тест;
  новая строка в HELP автоматически попадает в параметризацию обоих режимов. Проверки не пустые: ответ виден, нет «Ошибка хода»,
  `closing` только у /quit, заглушки /report /retire сравниваются с эталонной строкой в обоих режимах.

## Находки

### Средний приоритет
1. **Сторожевое значение «итого» в данных** — `game/commands.py::cost_rows/cost_lines`. Строка итога кодируется ролью `"итого"`,
   и `cost_lines` различает строки сравнением `role == "итого"`. Это смешение данных и подписи: в DataTable в колонке «Роль»
   оказывается «итого», а роль с таким именем сломала бы разбор. Предложение (просто, без абстракций): вынести литерал в
   константу `TOTAL = "итого"` в commands.py и сравнивать с ней в `cost_lines`; либо оставить как есть, но с константой. Менять
   форму кортежа не нужно.
2. **Тестовый хелпер `sections` поддерживает два формата** — tests/unit/game/test_cost_command.py. Ветка «итог последней строкой
   блока» мёртвая: реализация печатает итог первой строкой. Двухформатный разбор прячет регресс порядка (итог уедет вниз — тесты
   останутся зелёными). Предложение: оставить одну ветку (итог — первая строка блока), удалить вторую и комментарий «порядок не важен».
3. **Отчёт считается дважды и читает файлы в главном потоке** — ui/tui/app.py::finish_turn. `cost_report(self.game)` вызывается
   из UI-потока после worker'а (обход `*/meta/costs.jsonl`), хотя `/cost` уже посчитан в worker'е. Безопасно по потокам (worker
   завершён, риск D2 соблюдён), объём мал — правка не обязательна. Если править — без изменения `Reply`, оставить как есть, но
   добавить однострочный комментарий, почему отчёт пересчитывается (сознательное решение «не трогать Reply»).

### Низкий приоритет
4. `CostModal(TextModal)` вызывает `super().__init__(title, [])` и полностью переопределяет `compose` — наследование ради
   `on_mount`/Esc/кнопки; приемлемо, соответствует соседнему стилю. Без правки.
5. `strings.COST_COLUMNS` вставлена между `KEY_CLOSE` и `CLOSE`, разрывая пару строк закрытия. Предложение: перенести ниже `CLOSE`
   (рядом с MODAL_TITLES). Косметика.
6. Особый случай `first_words` → «Сессия» продублирован в test_commands_both_modes.py и test_tui_entry_points.py. Допустимо (тест-хелперы
   своих файлов, как в P3); если хочется — вынести в ui_kit. Без обязательной правки.
7. Поля `Totals.by_role`/`by_model` больше не используются в src (только тесты llm/master/boundary). Удалять не надо (тесты на них
   опираются, `make dead` их не ловит как поля dataclass) — просто отметка.

## Вопросы проектировщику

  требовал бы руками дописать тест, нет. Считаем это выполнением приёмки? (Ревьюер считает — да, это сильнее ручного списка.)
