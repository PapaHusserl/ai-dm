# Меню боя «сначала цель» — отличия от плана (kaban)

План: docs/COMBAT-MENU-PLAN.md, ответы проектировщика В1–В7 приняты.

## Отличия и решения по ходу
1. В7: «Другое оружие ▸» нет; каждая атака по цели — своя строка (оружие, безоружный, импровизированный, особые стрелы).
   Лимит `MAX_ROWS = 10` через `fit`: вытесняются по `RANK_BY_KIND` — переговоры/обезоруживание, затем рывок/отход/заклинания,
   затем уклонение/второе дыхание, движение, и только потом оружие; «Закончить ход» не вытесняется до оружия.
2. `MenuRow`/`MenuView`: добавлены `rank`, `block`, `group`; `TargetChip{ref, name, hp_text, rank}` без `zone_mark`/`letter`;
   ранг цели: 0 своя зона, 1 соседняя, 2 дальше (считает `screen.roster_of`). «Ещё…» — последняя строка `free_rows`;
   `MenuView.rows` — все видимые строки с клавишами («0» — десятая). Группы раскрытия: `move`, `spells_target`, `spells_free`.
3. `target_of(cast)` отдаёт сырой `params["target"]`; что это враг-участник, решает `build_view` по ростеру (зона/союзник/
   список — бесцелевой блок). Помощь и перенос метки на нецелевые — только в «Ещё…» (категория не задана).
4. `short_label(option, target)`: срезает « (ещё N из 2)» всегда, « → Имя» — только у вариантов выбранной цели;
   заголовок `header` = «ещё N из 2 атак».
5. «Оглушающий» (F3) держится до выключения, сбрасывается при смене боя. При вкл. у атаки без `:nonlethal` — пометка
   «(дальнобойным — не оглушить)».
6. `MoreModal`: полный плоский список с заголовками по затратам (`COST_TITLES`), без группировки по целям; цифры 1–9.
   Эхо в ленту — label варианта без номера.
7. `Block("turn_menu").args` получил 6-е поле `roster`; `simple.render` читает первые 5 (старые 5-элементные args живы).
   `format.head_lines` вынесена из `turn_menu_lines` (шапка меню).
8. `COMBAT_HINT_TUI` (strings) — подсказка для TUI; `COMBAT_HINT` остался для простого режима.
9. `pickable` не менялась: бой обрабатывает `MenuState` (`AiDmApp.check_action`/`action_pick`).
10. vulture: новые обработчики Textual (`on_combat_menu_picked`, `on_combat_menu_target_picked`, `action_next_target`,
    `action_prev_target`, `action_toggle_nonlethal`, `action_more_menu`, `action_menu_back`, `on_option_list_option_selected` для
    MoreModal) в `vulture_allowlist.py` не внесены — нужно согласие пользователя.

## Решения проектировщика (2026-10-06)
- Р-1. «Вырваться» (kind=escape) — в основном меню (блок без цели, первой строкой), когда герой опутан; не только в «Ещё…».
- Р-2. Новые обработчики Textual меню внесены в vulture_allowlist.py (согласие пользователя).

## Ревью mama-kaban

Хорошо: меню вынесено отдельным слоем (`ui/combat_menu.py`), движок и плоская нумерация протокола не тронуты. Простой режим изменился только в одном месте: `block.args[:5]`. `option_list` рассказчика (Choices) работает как раньше: цифры уходят в него, пока он показан. `fit` соответствует В7 и Р-1: escape имеет rank -2, оружие (rank 0) вытесняется последним, «Ещё…» добавляется после fit. Клик по строке и цифра проходят через один и тот же `menu.row` → `find` по id в том же `self.menu.options`, по которому строилось меню, поэтому рассинхрона видимой и плоской нумерации внутри одного хода нет. Tab при непустом поле отдаётся `Entry.complete`, модалки блокирует `menu_ready`.

Замечания по важности:

1. (средне) `app.py:on_input_submitted`: если в бою набрать число больше количества строк (например «12» и Enter), `menu.row` вернёт None, и текст «12» уйдёт в `start_turn` как ПЛОСКИЙ номер варианта движка. Так выполнится вариант, которого игрок на экране под этим номером не видел. Предлагается: при активном меню число вне диапазона не отправлять, а писать в ленту короткое «Нет такой строки». Вторая неувязка: в отличие от `action_pick`, здесь не проверяется `choices.display`, и при одновременном показе меню рассказчика цифра+Enter уйдёт в меню боя. Условие стоит сделать как в `action_pick`.
2. (средне) `screen.py:roster_of`: `[...][0]` упадёт с IndexError, если героя нет среди участников или у него нет зоны (смерть, бегство, сдача в переговорах). Нужно проверить, может ли `combat_blocks` вызываться в таком состоянии, и добавить на это тест. Других рисков по «концу боя» нет: `combat_map` и `turn_menu` всегда идут парой, и `menu.active` сбрасывается при обновлении без них.
3. (низко) `MoreModal`: в списке показаны плоские номера «N.», но цифровые привязки есть только для 1–9, без 0. Варианты с 10-го цифрой не выбрать. Кроме того, в бою у игрока теперь две нумерации на экране: в меню видимая, в «Ещё…» плоская. Предлагается в модалке либо убрать номера после 9, либо привязать к ним цифры так же, как в основном меню. Номера в модалке лучше не показывать там, где нажатие цифры ничего не выберет.
4. (низко, удобство) `TargetBar`: при переполнении (обычно 4 и больше врагов) остаётся одна строка «Цель: … Tab», и клик по ней только переключает цель по кругу. Для 4–6 врагов это терпимо. Дешёвое улучшение без смены плана: перед тем как сворачивать в одну строку, сокращать имена в чипах через `clip`, например до 10 символов, тогда кликабельные чипы чаще будут влезать.
5. (низко, A7) Латиница «Tab» в `strings.TARGET_ONE` попадает в видимый текст. В подсказке ленты уже написано «табуляция», значит и здесь можно было бы обойтись без латиницы: «Таб» или «⇥». Тогда исключение в тесте A7 не понадобится. F3/F4 в футере допустимы по прецеденту F2.
6. (низко) `CombatMenu.MAX_LINES = 24`: раскрытая группа (например «Заклинания на цель») может оказаться длиннее, и лишние строки молча обрежутся. Строки после 10-й показываются без номера и выбираются только кликом. Нужен тест на группу больше 10 и больше 24 строк, либо в группе тоже нужен `fit` со строкой «Ещё…».
7. (низко) `MenuState.find` → `MENU_GONE` в нормальном потоке недостижим: опции не меняются между отрисовкой и выбором. Это допустимая страховка, но тест на неё сейчас проверяет искусственное состояние.

Где явно не хватает тестов (вместо недоведённого mutmut):
- `fit`: равные rank в разных блоках, когда target_block идёт первым. Нужна проверка, что при нехватке места stabilize/multiattack вытесняются раньше атаки по цели.
- `MenuState.load`: смена `combat_id` сбрасывает цель и оглушающий, а при том же бое цель сохраняется, даже если она пропала из chips (тогда срабатывает fallback на первую).
- Нужен TUI-тест на ввод числа больше длины меню + Enter (п. 1) и на «0» → строка 10.
- `attack_row` при включённом оглушающем и отсутствии варианта `:nonlethal`, то есть пометка NO_STUN_NOTE.
- `roster_of`: ранги 0/1/2 и пропуск неактивных врагов (surrendered).

Вердикт: нужны правки по п. 1 (обязательно) и проверка п. 2. Остальное по желанию.
- Р-3. Латиница «Tab», «F3», «F4» в подсказках (строка целей, футер, подсказка ленты) — оставить как подписи клавиш;
  исключение в тесте A7 для этих слов — сознательное.
- Р-4. mutmut: `make mutate MOD=... TESTS="пути"` — фазы stats/clean и мутанты гоняют только указанные тесты
  (pyproject временно правится и восстанавливается) — согласие пользователя.

## Мутации `ai_dm.ui.combat_menu` (kaban-doeba)

Запуск: `make mutate MOD=ai_dm.ui.combat_menu TESTS="tests/unit/ui/test_combat_menu.py tests/unit/ui/tui/test_tui_combat_menu.py"`.
Первый прогон: 58 выживших; после дополнения тестов осталось 17, все эквивалентные или шумовые (код не менялся).

| Мутант | Что | Почему не закрыт |
|---|---|---|
| `option_row` 9, 11, 12 | `RANK_BY_KIND.get(kind, 6)` → `None` / без default / `7` | default недостижим: `option_row` вызывается только для kind из `CATEGORY_BY_KIND`, все они есть в `RANK_BY_KIND` |
| `attack_row` 25 | `option_row(..., target, label)` → `None` вместо target | label передаётся явно, `target` в `option_row` тогда не используется |
| `free_block` 32 | ранг группы «Идти ▸» 1 → 2 | эквивалентен: группа идёт первой в блоке, а при равном ранге вытесняется последний; соседи ранга 2 всегда позже |
| `group_rows` 29, 34, 35 | `block` строки подгруппы `None` / `"XXtargetXX"` / `"TARGET"` | в раскрытом режиме `block` не читается (строки сразу в `target_rows`) |
| `build_view` 35, 38, 41, 42 | `block` у строки «Ещё…» длинной группы | то же: после раскрытия `block` не используется |
| `build_view` 75, 78, 81, 82 | `block` у строки «Ещё…» основного меню | строка добавляется в `free_rows` уже после `fit`, `block` дальше не читается |
| `MenuState.load` 3 | `self.target = None` → `""` при смене боя | сразу перезаписывается `default_target` (для `""` его нет среди refs → то же значение) |

Закрыты тестами (основные группы): подписи без « → Имя» у переговоров/заклинаний/оглушающей/раскрытых групп, `clip`, `number` (нет ключа после 10-й строки), граница длинной группы (ровно 10 строк vs 15), ранги вытеснения (группа заклинаний, «Идти ▸», «Заклинания без цели ▸», переговоры), две зоны = группа, начальные значения `MenuState`, `view` с `expanded`.
