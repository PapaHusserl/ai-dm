## Решения проектировщика
- Р-1 (2026-10-06). Рисунок монстра на первом ходу боя сжимал «Бой» ниже «Героя» (нарушение live-1 п. 2).
  Решение: ограничить высоту рисунков монстров (и типов существ), чтобы «Бой» оставался выше «Героя» уже на первом ходу;
  рисунки монстров перерисовать под новый лимит. Раскладку не менять, тест live-1 не ослаблять.
- Р-2 (2026-10-06, заменяет Р-1). Лимит 4 строки для монстра в #picture признан слишком мелким. Решение: крупный рисунок
  монстра (≤ 36×14, как остальные) печатается в ленту при начале боя (один раз на бой) — сознательное исключение из
  «рисунки в ленту не печатаем»; в #picture рисунок монстра не выводится (в бою панель скрыта). MONSTER_MAX_ROWS убрать,
  рисунки монстров вернуть крупными.

## Ревью mama-kaban (2026-10-06)
Соответствие плану и Р-2: каталог `art/` (В-1), простой режим — только заставка (В-2), ASCII + ░▒▓ (В-3), монстр — крупно
в ленту один раз на бой, #picture в бою скрыт (Р-2 вместо Р-1/В-4), минимальный набор + BACKLOG 5а (В-5). Код простой,
в духе соседнего; `Text(line)` защищает от rich-разметки; сейвы и схема не тронуты.

Замечания (по важности):
1. Рисунки — кривые рамки (ширины строк одной рамки разные, правая граница «гуляет»): `cellar.txt` (29 и 32 — строки 2,9–10
   уже строк 3–8), `shop.txt` (крыша 28–30, тело 32), `city.txt` (правый край 26–29), `death.txt` (строка 6 `|  ,.''., |`
   на 1 короче соседних). Выровнять. Можно добавить сторож: у рисунка с рамкой `|...|` все строки рамки одной ширины —
   не обязательно, достаточно поправить файлы.
2. `vale.txt` и `village.txt` почти одинаковы (те же три дома, то же дерево) — Вейл должен отличаться (река уже есть —
   оставить её, деревню сделать другой: мост/колодец/поле).
3. «HERB» в `shop.txt` в текущем файле не найден (латиницы ≥ 3 букв в data/*.txt нет) — проверить, что исправление
   осознанное; добавить в сторож каталога запрет латинских букв (кроме одиночных декоративных `v`/`o`), чтобы не вернулось.
4. Мутанты `show_picture`/`restore_location_picture`: эквивалентность правдоподобна — (а) `picture_kind in ("monster","event")`
   → добавление "location" лишь перерисовывает ту же локацию; (б) `state.location is not None` — у героя локация есть
   всегда, ветка None недостижима в игре. Но (б) — тот же случай, что в коммите 4f4783c: недостижимая защита рождает
   эквивалентных мутантов; честнее убрать проверку (или `picture_state` гарантирует локацию). Номера 12–14, 24, 32
   сверить с выводом mutmut в отчёте партии (в review.md нет таблицы «мутант → почему эквивалентен» — дописать).
5. Заставка в TUI после выбора героя (HeroPickerApp — отдельное приложение): приемлемо для партии, простой режим ведёт себя
   так же. Перенос заставки в HeroPickerApp — в BACKLOG (мелочь, решение пользователя на живом прогоне).
6. `turn_events`: событие считается только у обычной строки; level_up/death от команды не дадут рисунок — допустимо,
   отметить в ARCHITECTURE F6 одной фразой.

## Мутанты партии P6 (kaban-doeba, mutmut по новым функциям)
Убиты все, кроме эквивалентных/шумовых; номера — из вывода `mutmut results`.

| Мутант | Что изменено | Почему эквивалентен |
|---|---|---|
| show_picture №12, №13, №14 | `query_one("#picture", Panel)` -> `None` / без типа / без аргумента | селектор `#picture` однозначен, тип нужен только для подсказки типов; поведение то же |
| show_picture №24 | `write_feed(text.split("\n"))` -> `split("XX\nXX")` | текст рисунка не содержит «XX\nXX», `split` отдаёт одну строку, на экране RichLog переносит по `\n` сам: вывод тот же |
| show_picture №32 | то же для `panel.show(...)` | Panel склеивает строки обратно через `\n`: итоговый текст тот же |
| restore_location_picture №1 | `text = None` -> `text = ""` | значение затирается или не используется: ветка `location is None` недостижима (у героя локация есть всегда), kaban убирает проверку |
| restore_location_picture №10 | `split("\n")` -> `split("XX\nXX")` | как №32 |

Выжившие на старых строках `ui.simple.run` (opening=None, пропуск opening, `line = None` вместо `take_opening()`): в BACKLOG 16.
