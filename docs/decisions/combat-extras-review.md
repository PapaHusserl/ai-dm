# Партия «Боевые дополнения» — заметки кабана об отличиях от плана

План: `docs/COMBAT-EXTRAS-PLAN.md`. Решения проектировщика 2026-10-06: В1 — импровизированное оружие фиксированным вариантом
меню (ближний + бросок 20/60); В2 — монаха не делаем; В3 — Опутывающий удар работает на импровизированное, не на безоружный;
В5 — бросок оставить. Схема сейва v5 не менялась.

## Отличия от плана
1. **Размер цели Опутывающего удара (В4).** По тексту SRD 5.2 Большие и крупнее НЕ имеют иммунитета: они проходят спасбросок
   Силы с преимуществом. Реализовано так (`attack.weapon_rider`, `engine.save(..., base_adv="advantage")`), а не «заряд
   тратится без эффекта». Размер: `Monster.size` / `species.size`, порядок tiny < small < medium < large < huge < gargantuan.
2. **Урон безоружного — без костей.** `AttackInfo.dice is None`, урон фиксированный `max(0, 1 + Сила)` (`attack.fixed_damage`,
   строка лога «Урон (безоружный удар): 1 + 3 Сила = 4 дробящий»); крит ничего не удваивает. В плане было «0d0/спец».
3. **Эффект на опутанной цели: id = id заклинания.** В плане `id="ensnared"`; взят `id="ensnaring_strike"`, `kind="ensnared"` —
   иначе `concentration_targets`/`lost_text` ищут заклинание `ensnared` в реестре и падают при потере концентрации.
4. **Апкаст.** Движок не поддерживает повышение круга (`cast_problem` отклоняет `bad_circle`), поэтому кости урона в заряде =
   `spell.level` костей (`{circle}d6`); в YAML добавлен `upcast.per_slot_level.dice: 1d6` для данных.
5. **Заряд попадает не по лежащей цели.** Если у цели после удара 0 HP, заряд не тратится (лозы на упавшем смысла не имеют) —
   решение кабана, плана нет.
6. **Конец боя.** В `end.conclude` концентрация героя на заклинании вида `rider` снимается (вместе с `restrained`/`ensnared` у
   NPC мира); иначе опутанный NPC оставался бы опутанным после боя. Плана не было.
7. **Скорость 0 у опутанного.** В плане сказано «уже есть» — на деле `restrained` скорость не обнулял. Добавлено в
   `available.move_options`: опутанный не получает вариантов `move:*` (действия остаются).
8. **Тактика рядовых.** `EngineTactics.pick_attack` не берёт `improvised*` (иначе авто-герои бросали бы подручное вместо
   шага к врагу); безоружный берётся, если оружия нет. `EngineTactics.choose_turn` первым выбирает `escape`.
9. **Вне боя** `cast_spell` для вида `rider` отклоняется: `Invalid(code="combat_only")`.
10. **Карточка героя** (`sheet_text`) строку «Безоружный удар» не получила (в плане «чтобы могла»; golden-вывод листа не менялся).
11. `ammo_options` пропускает атаки без `weapon_id` (иначе `registry.get("weapon", "improvised_thrown")`).
12. Провоцированная атака героя по-прежнему только оружием в руке (безоружного/импровизированного не берём).

## Ревью mama-kaban

Проверено: дифф src/ партии (attack, cast, standard, available, controllers, end, engine, opportunity, spellcasting, derived, resources, narrator_rules, ensnaring_strike.yaml) в контексте соседнего кода.

Хорошо: `dice=None` читается только в `attack.attack` (ветка `fixed_damage`); `mastery_of` отсекает `weapon_id is None`, `ammo_options` и `perform` (equip) тоже; `melee_attack_of` берёт только `main_hand`, поэтому unarmed/improvised в атаки по возможности не попадают. Снятие conditions в `drop_concentration_effects`/`drop_concentration` фильтрует строго по `expires.kind == "concentration"` и `owner` — чужие состояния не трогает (prone от topple, hidden и т. п. без `expires`/с другим owner остаются). `conclude` — единая точка конца боя, заряд снимается при любом исходе.

Замечания по важности:

1. `available.list_options` — опутанному (`restrained`) по-прежнему предлагается `flee` при выходе из зоны, хотя `move_options` уже возвращает [] (скорость 0). Предлагаю ту же проверку `restrained` перед добавлением `flee`.
2. Мутанты `escape` 20/26/44/46/60/61/65 — по коду это ветка монстра (`RollRequest`: `actor_id`, `ability`, `bonus_parts` с «Сил», `modifiers`) и строки лога; они не эквивалентны, это дыра в тестах: нужен тест, где монстр вырывается, с проверкой текста броска («Сил +N») и успеха/провала при граничной СЛ. `weapon_rider` 68 — скорее всего `params` эффекта `ensnared` (`dc`/`damage_type`); тоже не эквивалентен: escape и урон в начале хода читают их — проверить тестом «СЛ вырваться = СЛ заклинателя» и тип урона piercing в логе.
3. `fixed_damage` 22–24: `DAMAGE_TYPE_WORDS.get(info.damage_type, info.damage_type)` — тип всегда bludgeoning, фолбэк недостижим, мутанты эквивалентны. Сделать как в 4f4783c: `DAMAGE_TYPE_WORDS[info.damage_type]`.
4. Непокрытое тестами (по словам доебы) — нужны три коротких теста: `cast_spell` с rider вне боя → `combat_only`; `EngineTactics.pick_attack` не выбирает `improvised*` при наличии только их и оружия; `conclude` при обычной победе снимает `weapon_rider` и `concentration`.
5. `standard.escape` у монстра — голая проверка Силы, навык Атлетики монстра (если в данных есть skills) не учитывается. Для текущих монстров приемлемо, но комментарий «Сила, Атлетика» в метке опции вводит в заблуждение для NPC — упомянуть в decisions или учесть навык.
6. `cast_rider`: `circle = spell.level` — апкаст в движке не реализован (слот всегда `spell_slot:{spell.level}`), поэтому `upcast.per_slot_level` в yaml пока мёртв, а комментарий «на каждый круг выше 1-го» обещает больше, чем делает. Либо оставить пометку TODO в BACKLOG, либо убрать комментарий.
7. `spellcasting.drop_concentration` (вне боя) снимает с героя только `kind == "spell"`, а `weapon_rider` — нет. Сейчас недостижимо (conclude снимает заряд, вне боя rider не кастуется), но если заряд когда-то переживёт бой — повиснет. Достаточно комментария.
8. `EngineTactics.choose_turn`: escape безусловно первым — по плану ок; отмечу, что при Силе монстра намного ниже СЛ он будет тратить ходы впустую. Не правка, на заметку.

narrator_rules: правило про improvised/improvised_thrown/unarmed сформулировано точно, отличает от `improvise`. ОК.

Вердикт: нужны правки (п. 1 и тесты п. 2, 4; п. 3 — одна строка), остальное по желанию.

## Правки по ревью mama-kaban
- Опутанному не предлагается `flee` (как `move`).
- `fixed_damage`: `DAMAGE_TYPE_WORDS[...]` без `.get`.
- `escape` у монстра: в модели монстра нет навыков, бонуса Атлетики нет -- бросок идёт по модификатору Силы (если навыки появятся, брать Атлетику).
- Апкаст rider: комментарий исправлен, хвост -- BACKLOG 18.
- `spellcasting.drop_concentration`: комментарий про `weapon_rider`.
