## 1. Правила очереди

1. Партия с кодом — полный конвейер (kaban + kaban-doeba по diff и списку функций, mutmut по изменённым функциям,
   mama-kaban). Партия «данные» (помечена «д») — облегчённый: загрузка реестра, `test_classes_build`/тест загрузки
   конфига, выборочные бои sim_combat, тест стабильности кэшируемого префикса (где есть промпт), mama-kaban.
   «M+д» = одна партия кода M и следом одна партия данных (считаются как две единицы работы, один номер в очереди).
2. Миграции нейтральны по поведению (решение 5), паузы живой игры нет. Тест «тот же ход по сиду до/после» обязателен
   для К0, Ж0, М0, С0.
3. Ни одна партия, кроме К0/Ж0/М0/С0, не меняет схему. Если на груминге партии выясняется, что нужно поле — стоп и
   вопрос проектировщику (иначе появляется v12 и сдвиг).
4. Цена хода ≤ ~$0.03, `cache_write/read` замеряются на каждом живом прогоне (решение 7); рассказчика не урезать.
5. **Правило перестановки по условию** (для ступеней К II/III): партия стоит на своём месте и делается там, даже если
   условие не наступило. Если условие наступило раньше, партию можно поднять в указанную «раннюю точку» без
   пересмотра плана — обе точки лежат после всех её зависимостей и схему не трогают.
