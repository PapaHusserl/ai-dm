## Замечания
- llm/journal.py `records_for`, ранний выход (вопрос тестировщика). Сценарий пропуска: нужный прогон A кончается в
  сегменте k, сегмент k+1 начинается с чужого прогона X, затем идёт нужный B — выход на k+1, A потерян. Для этого
  между прогонами одного хода должен вклиниться чужой прогон. Сейчас ход однопоточен: основной `run-*`, затем
  граница `bnd-*` (world, summarizer) синхронно в `close_scene_if_needed` — подряд. Retry (`turn.py:212`) переносит
  `started.run_ids` старой попытки и добавляет новые прогоны в рамках той же цепочки; `resume_boundary` после
  загрузки — новый ход со своим run_id. Чужому прогону вклиниться неоткуда, то есть на текущем коде нереально.
  Правило то же, что в `mark_turn`, — согласованно. Предложение: не менять, а дописать в комментарий
  предпосылку «прогоны хода идут в журнале подряд»; если когда-нибудь появится фоновый summarizer или retry
  после чужого хода — переделать на «выход, когда все wanted начались не с начала сегмента».
- reports/writer.py `write_journal`: отсутствующий блоб молча пропускается (`if blob.exists()`), а
  `meta.replayable` остаётся true. Для P2 это даст непонятный сбой воспроизведения. Предложение: при пропавшем
  блобе ставить `replayable=false` (или хотя бы строку в report.md). Не блокер — блобы сейчас не удаляются
  ротацией сегментов.
- reports/markdown.py `message_lines`/`call_lines`: текст блоков оборачивается в ``` без экранирования; рассказ
  или tool_result с ``` внутри сломает разметку report.md. Только косметика чтения, calls.jsonl — источник истины.
  Можно оставить.
- game/turn.py `capture_of`: deep copy всего бандла теперь на каждом ходу (after), даже без репорта. Плата за
  корректный ручной `/report` после выбора уровня/тона; по объёму бандла приемлемо, но держать в уме, если ход
  станет медленным.
- Детерминизм для P2: `before/` содержит RNG до хода, `calls.jsonl` — запросы/ответы по порядку с call_id и
  attempt — достаточно для воспроизведения через мок. `saved_at` берётся из `now` репорта, а не хода — на
  сравнение состояний P2 не влияет, если сравнивать без `saved_at`; учесть в P2.
