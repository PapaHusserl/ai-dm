# 60. Сетевой сбой summarizer не уходит в запасную модель
status: done
priority: low

✅ (Т60, 2026-10-15) (из BACKLOG 59; приоритет — мини-партия сразу после коммита B59, решение проектировщика 2026-10-14)
503 после повторов роняет границу сцены в меню ошибки; `SummarizerSession.chain` переключается на запасную модель только при `refusal`/`invalid`.
Живой ход 399 (2026-10-14, 16:17–16:24): 503 ×2, затем 504 по таймауту 180 с — граница сцены ждёт до ~12 мин (`[retry] delays=[1,3,10]`, `timeout_s=180`). Направление: уходить в запасную модель после первого 503/504 на границе; пересмотреть таймаут. Там же: в 16:21–16:27 соединение висело в `SYN_SENT` по IPv6 (IPv6 до googleapis не работал, IPv4 — 0,5 с) дольше `timeout_s` — таймаут не покрывает подключение; нужен таймаут на connect и/или откат на IPv4. UX (ход 399, 16:30): «сменить модель» в меню ошибки меняет только упавшую роль — после смены summarizer рассказчик остался на перегруженном gemini и упал следом; при сбое провайдера предлагать сменить сразу обе роли. Решение проектировщика 2026-10-15: цепочка рассказчика `gemini-3.8-flash` → `gemini-4-argon` → `gemini-3-flash-preview` → `gemini-3.5-flash-lite` (только Gemini; OpenAI отложен — BACKLOG 65). Сеть (решение 2026-10-15, вариант А): флаг `[llm] gemini_ipv4 = true` по умолчанию (IPv6 до googleapis сломан с 14.10, раньше работал — флаг можно выключить) + общий таймаут Gemini 60–90 с; отдельный connect-таймаут не делаем.
