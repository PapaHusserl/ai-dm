status: done

(от дашборда)

Пришло из дашборда (`~/projects/dashboard`), поручено ai-dm целиком. Сейчас проект ведёт docs/ по-своему, и
дашборд не может его прочитать: `docs/HANDOFF.md` вместо `docs/handoff.md`, нет `docs/RULES.md` и `docs/done/`,
пункты беклога без строк `status:` / `priority:` / `updated:`, планы шагов как `docs/<ШАГ>-PLAN.md`, в `docs/`
лежат чек-листы прогонов `checklist-*-live.md`, нет AGENTS.md/CLAUDE.md в корне, `.dashboard.json` не в `.gitignore`.
1. Новая форма файлов: положить правила — `mix dashboard.scaffold --rules ai-dm` (из каталога дашборда) или
   скопировать `~/projects/dashboard/docs/RULES.md`; привести ROADMAP, BACKLOG (шапка пункта, статусы),
   handoff, `docs/done/` (закрытые пункты — карточками), документы шагов `docs/plan-<шаг>.md` к этим правилам.
2. Применить правила: закрытые и снятые пункты беклога — в `docs/done/`; решения — в документы шагов или NOTES.md.
3. Гигиена: чек-листы, отчёты, черновики — из репо (что нужно — в документ шага); строка `/.dashboard.json`
   в `.gitignore`; закоммитить или убрать незакоммиченное, `git status` чист.
Развилки (что удалять, как переименовать старые планы) — вопросом владельцу.
Решения владельца (2026-10-17, партия 22д): чек-листы `checklist-*-live.md` — пройденные удалить, непройденные
вынести из репо; старые `<ШАГ>-PLAN.md` — забэкапить старую раскладку и полностью перейти на новый формат
с миграцией данных (без «старые оставить как есть»); HANDOFF.md → handoff.md, закрытые пункты → карточки docs/done/,
`campaigns/test/` и `docs/import-examples/` — посмотреть и предложить (коммит или .gitignore) до действия.
