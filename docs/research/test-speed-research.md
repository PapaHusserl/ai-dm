# Ускорение тестов и разбора мутантов в ai-dm: ресёрч кабана-кволити (2026-10-25)

Источник для шага 202 (docs/plan-202.md). Ресёрч сделан вне шага, во время ДН; ничего не ставил и не менял, полный
прогон не запускал. Цифры — гипотезы до замера в шаге 202.

## Замеры и разведка
- `make cov` = `pytest -q --cov`, тесты идут последовательно: 21 912 тестов за 3685 с (61 мин). Средняя нагрузка в начале прогона 20–31, в конце 4–24 — машина была занята, около 0,17 с на тест.
- Ядер 8. pytest-xdist и testmon не установлены. В dev-зависимостях: pytest 9.1.1, pytest-cov 7.1.0, coverage 7.16.2, mutmut 3.8.0. Почему xdist не используется, нигде не записано. Вероятные причины — монолитный `make cov` и общий `pythonpath`: 14 каталогов тестов лежат в sys.path, модули с одинаковыми именами в разных каталогах могут конфликтовать.
- Выборка: `test_master_prompt.py` + `test_time_ops.py` дали 156 тестов за 5,5 с (около 0,035 с на тест), это быстро. `tests/unit/ui` за 400 с дошёл только до 83 % (оценка — около 8 мин на ~1,8 тыс. тестов, то есть около 0,25 с на тест). Тесты Textual-UI (`run_test`/Pilot) — самая медленная часть.
- Импорт `ai_dm.ui.screen` — 0,5 с, вместе с `game.boundary` — 0,24 с. Одноразовая цена на процесс, не узкое место.
- conftest: autouse-фикстуры дешёвые (durable off, патч дефолтов). Фикстур уровня module/session — 18.
- mutmut 3.8 поддерживает `max_children` (флаг `--max-children`), `do_not_mutate`, `mutate_only_covered_lines`, `type_check_command` (нашёл в исходниках установленного пакета, семантику по документации не проверял). Мутаций только по строкам диффа в mutmut нет.

## Меры: выигрыш / риск / зависимость

1. **pytest-xdist (`-n auto` или `-n 6`, распределение `--dist loadfile`) для `make cov` и полного pytest.** Оценка: 61 → 12–18 мин на свободной машине; при соседних прогонах — 20–30 мин (не замерено). pytest-cov поддерживает xdist сам. Риск: тесты, зависящие от порядка или общего состояния (глобальные `set_durable`, `APP_DEFAULTS_PATH`, файлы в общих путях) — нужен пробный прогон и разбор падений. Покрытие не теряется. **Новая зависимость:** pytest-xdist (MIT, активно развивается) — нужно согласие Влада. Проверять `-p xdist --dist loadfile -n 6` один раз; при конфликтах имён из `pythonpath` — `--import-mode=importlib`.
2. **Для mutmut: `max_children` в `[tool.mutmut]` или флаг `--max-children`.** mutmut по умолчанию и так берёт число ядер; на общей машине лучше явно 4–6, чтобы не душить соседей. Выигрыш — стабильность, а не скорость. Без зависимости, это правка конфига.
3. **Сужение мутантов до строк диффа.** mutmut этого не умеет. Сейчас сужаем до функции (FUNCS) — отсюда 62 выживших в `PromptBuilder.state_data`, хотя менялись 2 строки. Вариант без зависимости: скрипт в devtools, который после `mutmut run` фильтрует `mutmut results` по номерам строк из `git diff -U0` (через `mutmut show` и сопоставление строк). Оценка: время прогона то же, разбор агентом сокращается в разы (с 62 до нескольких мутантов). Это и есть правило 4 из «Экономии конвейера», только автоматически. Риск — низкий: старые строки и так уходят в BACKLOG.
4. **Отсев шумовых мутантов (тексты сообщений).** `# pragma: no mutate` на строках с f-строками/константами сообщений или `do_not_mutate` (глобы файлов, например `*/prompts/*`, модули констант текстов). Выигрыш: меньше мутантов (оценка −10–30 % в UI и master) и меньше разбора. Риск: если текст — это контракт (парсер, промпт), мутанты там полезны; глушить только тексты для человека. Решает Влад, запись allowlist — с его согласия. Без зависимости.
5. **`mutate_only_covered_lines = true`.** Не порождать мутантов на строках, которые TESTS не покрывают: они заведомо выживут или останутся без тестов. Выигрыш: меньше мутантов, нет мусора от узкого TESTS. Риск: непокрытое уходит из счёта, его должен ловить порог cov. Без зависимости, семантику проверить на одном прогоне.
6. **testmon (pytest-testmon) для итераций.** Гоняет только тесты, которые затронуты изменёнными строками (по данным coverage). Оценка: итерация — секунды или минуты вместо выбора файлов вручную. Риск: пропускает зависимости от данных (toml/md-промпты, content/) — поэтому полный прогон в конце партии оставить. С `--cov` совмещается плохо; держать как отдельную цель `make test-fast`. **Новая зависимость** (MIT) — нужно согласие.
7. **Быстрый и медленный контуры.** Маркер `slow` на Textual-Pilot-тестах (`tests/unit/ui/tui` и др.): во время итераций `-m "not slow"`, полный прогон — в конце партии. Без зависимости. Оценка: около 8 мин UI выпадают из итераций.
8. **Профиль медленных тестов.** В конце партии добавить `--durations=30` к `make cov` (без зависимости). Цель — найти топ (UI, сценарии с `golden/`) и вынести дорогой setup в фикстуры уровня module. Выигрыш — по итогам замера.
9. **`make cov` с `--cov-branch`/`--cov-context` не включать** — это замедлит.
10. Дублирующие тесты и параметризации по 21,9 тыс. — отдельный аудит (кабан-доеба) против мутантов. Не механически: удалять только тесты, которые не убивают уникальных мутантов.
