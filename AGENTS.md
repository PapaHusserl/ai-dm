# ai-dm

Текстовая RPG по D&D 5e (SRD 5.2) с ИИ-мастером: Python, uv. Пользователь — проектировщик, продуктовые решения только его.
Отвечать по-русски.

Правила ведения docs/ROADMAP.md, docs/BACKLOG.md, docs/handoff.md, docs/done/ и гигиены репо — @docs/RULES.md

## Где что

- ТЗ — docs/TZ.md (этапы — раздел 13), архитектура — docs/ARCHITECTURE.md (части A–E), адаптации правил — docs/rules-adaptation.md,
  термины — docs/glossary.md. Тегов `stage-*` в репо нет (есть только `k0`).
- Каждый шаг — docs/plan-<шаг>.md: суть, решения проектировщика, правки по ревью, итог (расход, тесты, находки).
  Ресёрчи — docs/research/. Закрытые пункты беклога — docs/done/.
- ~/.config/ai-dm/checklists/ — чек-листы живых прогонов (не в репо).

## Как работаем

- Оркестратор (основная сессия) ведёт конвейер агентов. Груминг — svinopas (мини-влад) + kaban-svekrov (аудит); план —
  papa-kaban; после «окей, кабаним» — kaban (код, src/docs) и kaban-doeba (тесты, tests/**) параллельно; затем mama-kaban
  (ревью), правки, коммит оркестратором. Финансы — kaban-test. Архитектор — kaban-arhitektor (роадмап).
- Правки вне ~/msa — через Edit/Write; у kaban/doeba Edit намеренно нет, мелкие правки после ревью вносит оркестратор.
- Перед каждым коммитом — обновить docs/ROADMAP.md (его ведёт только архитектор). Коммит — после каждой принятой партии:
  только нужные пути, НЕ `git commit -a`; без чек-листов и отчётов. Remote — приватный GitHub PapaHusserl/ai-dm (origin),
  после коммита партии `git push`. Хэши коммитов до 4978d2e — из утраченной истории (`.git` пересоздан 2026-10-11).
- Перед живым прогоном пользователя готовить чек-лист в ~/.config/ai-dm/checklists/checklist-<партия>-live.md; итог прогона —
  в «Итог» документа шага. Отчёты ревью и аудита — в разделы документа шага.
- Ключи API не печатать и не логировать. Живые вызовы API — только пользователь. saves/ — живые миры пользователя: агентам
  только читать (копии — во временном каталоге); правка сейва — только с согласия пользователя и с бэкапом.
- Глобально (~/.claude/CLAUDE.md): между партиями чистить контекст, состояние — в docs; ревью партий не сокращать.
- Решения по экономии: не урезать длину/мышление рассказчика, экономить на кэше/входе.
- Расход и модель каждой роли партии записывать в «Итог» её документа шага.

## Тесты и качество

- `uv run pytest -q` — около 17000 тестов, ≈ 45 мин без xdist; во время итераций — только затронутые файлы.
  `uv run ruff check src tests`.
- Перед коммитом партии: `make cov` (≥ 94 %), `make smells` (≤ 200), `make dead`,
  `make mutate FUNCS="модуль:функция модуль:Класс.метод" TESTS="tests/..."` по изменённым функциям
  (старый вариант — `MOD="..."`; TESTS — только тесты этих модулей, иначе stats/clean гоняют весь tests/ по ~12 мин;
  при устаревшем mutants/ — удалить каталог, он генерируемый). FUNCS разворачивается в шаблоны mutmut
  `ai_dm.mod.x_func__mutmut_*` и `ai_dm.mod.xǁClassǁmethod__mutmut_*`; пример:
  `make mutate FUNCS="ai_dm.ui.session:PlaySession.submit" TESTS="tests/unit/ui"`.
- vulture_allowlist — только с согласия пользователя. Партия не повышает smells (правило нулевого баланса).

## Экономия конвейера (приняты пользователем 2026-10-05)

1. mutmut — только по функциям, изменённым в партии (из `git diff`), запуск фоном; агент лишь разбирает результат.
2. Полный `pytest` и `make cov` — один раз в конце партии; во время итераций — тесты затронутых модулей.
3. Мутантов разбирает kaban-doeba (или кабан-кволити), а не kaban.
4. Выжившие мутанты разбираются только на новых строках партии; старые — сразу в BACKLOG.
5. Решения проектировщика сразу записывать в документ шага.
6. Токены и время субагентов каждой партии записывать в «Итог» документа шага.
7. kaban-doeba получает diff партии и список изменённых функций (`модуль:функция`), mutmut — `make mutate FUNCS=…`; разбор
   выживших — отдельным вызовом меньшей модели (sonnet/haiku) по выводу `mutmut results`. Глобальные агенты
   (`~/.claude/agents/`) правятся только через skill-intake.
